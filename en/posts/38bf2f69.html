ComfyUI开发之——ComfyUI工作流下载导入修改与分享(4.1)

一、概述

二、ComfyUI 工作流有哪些格式？

2.1 常见格式

在下载工作流之前，先了解几种常见格式。

格式 说明 常见用途
JSON 工作流 保存节点、连线和参数等信息 导入画布继续编辑
PNG / WebP 图片 部分图片内嵌工作流元数据 从生成结果恢复工作流
API JSON 保存面向 API 执行的节点提示数据 程序调用工作流

2.2、普通工作流 JSON 与 API JSON 有什么区别？

前面提到，两者虽然都使用 JSON 格式，但用途不同。

对比项目 普通工作流 JSON API JSON
主要用途 画布编辑 程序提交生成任务
节点布局 通常包含 不包含画布布局
节点连线 保存为工作流结构 使用节点输入引用组织执行数据
适合用户 日常搭建和修改 Python、HTTP API 调用
直接拖入画布 通常可以 通常不可以

如果后续要通过 Python 或其他客户端调用 ComfyUI，就需要了解 API 工作流格式。

通常可以在 ComfyUI 中通过工作流菜单找到导出 API 格式的入口。不同版本的菜单位置可能有所变化。

第 28 篇会专门介绍如何通过 HTTP 调用 ComfyUI 工作流。

2.3 注意事项

三 相关操作

3.1、从哪里下载 ComfyUI 工作流？

目前常见的工作流资源主要来自以下几个渠道。

1. ComfyUI 官方示例

官方示例适合初学者，通常能够了解某种模型或功能的标准使用方式。

  • ComfyUI 官方网站：https://www.comfy.org/
  • ComfyUI GitHub：https://github.com/Comfy-Org/ComfyUI
  • ComfyUI 示例工作流：https://comfyanonymous.github.io/ComfyUI_examples/

建议刚开始学习时优先使用官方示例，能够减少模型和节点版本不匹配的问题。

2. Civitai

Civitai 是比较常见的 AI 模型和工作流分享平台。

https://civitai.com/

可以找到：

  • 文生图工作流
  • 图生图工作流
  • LoRA 示例
  • ControlNet 工作流
  • 人像生成与修复工作流

部分资源会同时提供模型和工作流，下载时要仔细查看说明。

3. OpenArt

OpenArt 提供了大量 AI 图片和工作流资源。

https://openart.ai/

可以按照生成效果查找工作流，例如人物写真、动漫风格、产品图片、图片编辑等。

4. GitHub

GitHub 上有大量 ComfyUI 自定义节点和项目示例。

https://github.com/

适合查找：

  • 特定模型的工作流
  • 自定义节点示例
  • 自动化处理流程
  • 项目配套工作流

下载时建议优先选择官方仓库或维护活跃、说明完整的项目。

注意： 不要因为工作流能生成漂亮图片就直接运行其中的所有节点。对于来源不明的自定义节点、脚本和模型文件，要先检查项目说明和代码，避免运行不可信代码。

3.2、如何导入别人分享的工作流？

ComfyUI 常见的导入方式有三种。

1. 导入 JSON 文件

假设下载了一个工作流文件：

打开 ComfyUI 后，可以直接将 JSON 文件拖入画布。

部分版本也可以通过界面中的工作流打开功能选择 JSON 文件。

导入成功后，画布会显示对应的节点、连线和参数。

2. 从图片中恢复工作流

有些用户分享的不是 JSON 文件，而是生成完成的 PNG 图片。

如果图片保存时包含了 ComfyUI 工作流元数据，可以直接将图片拖入 ComfyUI 画布。

ComfyUI 会尝试读取图片中的元数据并恢复对应工作流。

需要注意：

  • 并不是所有 PNG 图片都包含工作流。
  • 图片经过某些网站压缩、格式转换或二次编辑后，元数据可能丢失。
  • 普通截图通常无法恢复完整工作流。

所以，分享工作流时，最好同时保存 JSON 文件和原始生成图片。

3. 使用界面打开工作流

不同版本的 ComfyUI 界面可能有所区别。

通常可以在工作流菜单中找到打开或加载工作流的入口，选择本地 JSON 文件即可。

导入后建议先不要立即运行，先检查节点和模型依赖。

3.3、导入后为什么不能直接运行？

这是初学者最容易遇到的问题。

工作流只是保存了生成流程，并不意味着运行它所需的所有资源也已经安装。

通常需要检查以下几个方面。

1. 自定义节点缺失

如果工作流使用了额外安装的节点，而本地没有对应节点，导入时可能出现缺失节点提示，画布中也可能显示无法识别的节点。

例如：

  • IP-Adapter 相关节点
  • ControlNet 预处理器节点
  • 图片背景移除节点
  • 视频处理节点
  • 第三方采样或图像处理节点

解决方法：

首先记录缺失节点的名称，找到它所属的自定义节点项目。

如果使用 ComfyUI Manager，可以通过其中的缺失节点查找或安装功能进行处理。不同版本的 Manager 界面和功能入口可能不同。

也可以根据项目官方仓库说明手动安装。

然后按照项目说明安装依赖。

如果需要安装 Python 依赖，一定要使用当前 ComfyUI 对应的 Python 环境，而不是随意使用系统 Python。

安装完成后重启 ComfyUI，再重新打开工作流。

2. 模型文件缺失

工作流可能引用了本地没有下载的模型。

常见模型包括：

模型类型 常见存放目录
Checkpoint models/checkpoints/
LoRA models/loras/
VAE models/vae/
ControlNet models/controlnet/
CLIP Vision models/clip_vision/
Upscale Model models/upscale_models/
扩散模型 models/diffusion_models/
文本编码器 models/text_encoders/

例如，工作流需要一个 SDXL Checkpoint：

就需要将模型放入对应的 Checkpoint 目录，或者在模型加载节点中选择正确的文件。

如果模型已经放入目录，但下拉列表没有显示，可以尝试刷新模型列表或重启 ComfyUI。

还要注意模型架构是否匹配。

例如：

  • SD 1.5 的 LoRA 通常不能直接用于 SDXL。
  • SDXL 的工作流不能随意替换成 SD 1.5 模型。
  • FLUX 工作流需要对应的模型、文本编码器和 VAE 等资源。
  • IP-Adapter、ControlNet 等模型也需要匹配对应架构和节点实现。

不能只看文件名相似就认为可以直接替换。

3. Python 依赖缺失

部分自定义节点除了代码，还需要额外的 Python 库。

例如，某些图片处理节点可能依赖：

  • opencv-python
  • insightface
  • onnxruntime
  • segment-anything

具体依赖以节点仓库的 requirements 文件和安装说明为准。

如果使用便携版 ComfyUI，通常需要使用其自带的 Python 环境安装依赖。

如果使用虚拟环境安装版，则需要进入对应虚拟环境。

不要直接把依赖安装到另一个 Python 环境中，否则可能出现安装成功、ComfyUI 仍然无法使用的情况。

3.4、如何修改下载的工作流？

工作流导入成功后，不建议一开始就大幅修改。

更好的方法是先理解原有流程，再逐步调整。

1. 先保存一份副本

2. 找到几个关键节点

对于常见的文生图工作流，优先检查以下节点：

节点 主要作用 常见修改内容
Load Checkpoint 加载基础模型 更换模型
CLIP Text Encode 编码提示词 修改正向、负向提示词
Empty Latent Image 创建初始潜空间 修改宽度、高度、批量数量
KSampler 采样生成 修改 Seed、Steps、CFG 等
VAE Decode 解码图片 通常不需要修改
Save Image 保存图片 修改输出文件名前缀

不同模型的工作流可能使用不同的节点组合。

例如，FLUX、Qwen Image 等模型的文本编码和采样流程与传统 SD 1.5 工作流并不完全相同，不要直接套用上面的节点结构。

3. 一次只修改一个地方

建议按照下面的顺序练习：

第一步：修改正向提示词，观察生成效果。

第二步：修改 Seed，观察随机变化。

第三步：修改图片宽度和高度。

第四步：修改 Steps、CFG 等采样参数。

第五步：尝试更换模型或 LoRA。

每次修改后运行一次，确认效果和原工作流之间的区别。

这样更容易定位问题，也能逐步理解工作流的结构。

四、如何分享自己的工作流？

当我们成功搭建一个工作流后，也可以分享给其他人使用。

建议至少准备以下内容：

分享内容 说明
工作流 JSON 方便别人导入和编辑
效果图片 展示最终生成效果
模型清单 说明需要哪些模型
自定义节点 说明需要安装哪些节点包
ComfyUI 版本 说明测试时使用的版本
参数说明 说明关键参数和使用方法
输入图片 如果工作流依赖参考图，需要说明如何准备

如果分享的是 PNG 图片，也可以保留原始工作流元数据，方便别人直接拖入 ComfyUI 恢复流程。

还需要注意模型和 LoRA 的授权许可。不要未经允许就重新打包或分发受限制的模型文件。

五、常见问题排查

问题 可能原因 处理方法
JSON 拖入没有反应 文件格式不正确或文件损坏 确认是否为普通工作流 JSON
导入后节点缺失 没有安装对应自定义节点 使用 Manager 或手动安装
模型下拉列表找不到文件 路径错误或列表未刷新 检查模型目录并刷新
工作流提示输入图片不存在 引用的是分享者电脑上的路径 重新选择本地图片
节点显示红色或无法连接 节点版本或接口不兼容 检查节点版本及连线
安装节点后仍然无法使用 Python 依赖缺失或环境错误 检查 ComfyUI 对应 Python 环境
生成效果与分享图片不同 模型、参数、Seed 或版本不一致 对照原始配置逐项检查
显存不足 模型或分辨率要求过高 降低分辨率、使用低显存配置

六、动手练习：下载并修改一个工作流

建议通过下面的练习熟悉整个流程。

练习目标： 下载一个简单的 SD 1.5 或 SDXL 文生图工作流，完成导入、依赖检查和修改。

  1. 从 ComfyUI 官方示例或可信社区下载一个文生图工作流。
  2. 将 JSON 文件导入 ComfyUI。
  3. 检查是否存在缺失节点。
  4. 检查 Checkpoint、VAE 等模型是否齐全。
  5. 修改正向提示词。
  6. 修改图片尺寸和 Seed。
  7. 运行工作流，观察生成效果。
  8. 将修改后的工作流另存为新的 JSON 文件。

完成后，你就掌握了下载、导入、修改和保存别人工作流的基本方法。

七、总结

ComfyUI 工作流可以重复使用，也可以在别人的基础上继续修改。

真正需要掌握的不只是如何导入 JSON，而是理解工作流背后的依赖关系：

  • 工作流文件负责保存节点和参数。
  • 自定义节点负责提供额外功能。
  • 模型文件负责提供生成能力。
  • Python 依赖负责支持节点运行。
  • ComfyUI 版本和节点版本会影响兼容性。

以后下载工作流时，建议先检查依赖，再运行和修改。
