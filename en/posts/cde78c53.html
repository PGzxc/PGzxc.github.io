一、概述

二、ComfyUI错误及查看

2.1、ComfyUI 出现问题，先从哪里开始？

遇到错误时，不建议立即重新安装 ComfyUI。

因为重新安装可能无法解决真正的问题，还可能导致模型、节点和工作流丢失。

建议按照下面的顺序排查：

  1. 确认错误发生在哪个阶段。
  2. 查看 ComfyUI 终端日志。
  3. 检查工作流是否缺少节点。
  4. 检查模型文件是否存在。
  5. 检查 Python 依赖和版本。
  6. 检查显存和系统资源。
  7. 尝试使用简单工作流验证环境。

可以先判断错误属于哪一类：

错误阶段 常见原因
启动时 Python 环境、依赖冲突、自定义节点
导入工作流时 缺失节点、工作流格式、版本差异
加载模型时 模型文件缺失、格式或架构不兼容
执行节点时 输入错误、节点异常、依赖问题
生成过程中 显存不足、运行库错误
保存图片时 输出路径、磁盘空间或权限问题

2.2、如何查看 ComfyUI 错误日志？

日志是排查问题最重要的信息来源。

ComfyUI 出现错误时，通常会在启动终端或控制台中显示详细信息。

如果使用 Windows 便携版，一般可以通过启动 ComfyUI 的 .bat 文件查看终端输出。

如果使用桌面版，则需要查看对应版本提供的日志或控制台信息。

1. 重点关注哪些内容？

常见错误关键词：

错误关键词 可能原因
ModuleNotFoundError Python 模块缺失
ImportError 模块导入失败或版本不兼容
FileNotFoundError 文件或模型路径不存在
CUDA out of memory 显存不足
RuntimeError 运行时错误，需要结合上下文判断
DLL load failed 动态库或运行环境问题
No such file or directory 文件路径错误
Connection refused 服务未启动或连接地址错误

需要注意，错误关键词只能帮助定位方向，不能单凭一个词就判断具体原因。

排查时重点关注：

  • 最后几行错误信息。
  • 报错涉及的节点名称。
  • 报错文件路径。
  • 缺少的模块名称。
  • 错误发生在加载模型还是执行节点时。

通常，最后一行异常信息能够提供最直接的线索。

如果需要向别人求助，建议提供完整错误日志，而不是只截取一句报错。

三、ComfyUI常见错误

3.1、ComfyUI 启动失败怎么办？

如果 ComfyUI 无法启动，可以按照下面的流程排查。

1. 检查是否安装了新节点

如果安装某个自定义节点后，ComfyUI 无法启动，首先怀疑该节点或它的依赖。

可以尝试：

  1. 关闭 ComfyUI。
  2. 打开 custom_nodes 目录。
  3. 找到最近安装或更新的节点。
  4. 暂时将节点目录移出 custom_nodes。
  5. 重新启动 ComfyUI。

如果移除节点后可以正常启动，说明问题可能与该节点有关。

例如：

可以暂时移出最近安装的节点，逐个排查。

注意：不要一次删除所有节点，否则可能导致原有工作流无法使用。

2. 检查 Python 依赖

如果日志出现：

通常说明当前 ComfyUI Python 环境中缺少对应模块。

解决方法：

  • 查看报错涉及的节点。
  • 找到节点项目的 README 或 requirements 文件。
  • 使用 ComfyUI 对应的 Python 环境安装依赖。
  • 重启 ComfyUI。

不要直接使用系统 Python 安装依赖，因为它可能不是 ComfyUI 实际使用的环境。

3. 检查依赖版本冲突

有些节点需要特定版本的 Python 库。

例如，更新某个节点后，可能导致其他节点依赖的库版本发生变化。

如果出现这种情况：

  • 查看节点官方安装说明。
  • 检查当前依赖版本。
  • 尝试恢复兼容版本。
  • 避免盲目升级全部依赖。

如果环境已经严重混乱，可以考虑在备份工作流和模型后，建立一个干净的 ComfyUI 环境进行测试。

3.2、工作流提示缺失节点怎么办？

下载别人分享的工作流时，经常会遇到缺失节点。

例如：

或者工作流中出现无法识别的节点。

1. 先确认节点名称

记录缺失节点名称。

然后判断它属于：

  • ComfyUI 自带节点。
  • 第三方自定义节点。
  • 已经更名或删除的旧节点。

如果属于第三方节点，可以使用 ComfyUI Manager 的缺失节点查找功能，或根据节点名称搜索对应项目。

Manager 的菜单和功能会随着版本变化，应以当前版本界面为准。

2. 安装节点后重启

安装完成后，通常需要重启 ComfyUI，才能加载新节点。

如果节点仍然缺失，需要进一步检查：

  • 节点是否安装在正确目录。
  • 是否存在多层重复文件夹。
  • Python 依赖是否安装成功。
  • 节点是否支持当前 ComfyUI 版本。
  • 启动日志是否出现加载错误。

3. 旧节点和新节点可能不兼容

有些工作流使用较旧版本的节点。

更新节点后，可能出现：

  • 输入参数发生变化。
  • 输出端口发生变化。
  • 节点名称改变。
  • 原有连线失效。

如果工作流原作者明确指定了节点版本，可以尝试使用对应版本。

对于重要工作流，建议在更新节点之前先备份。

3.3、模型缺失或模型无法加载怎么办？

模型问题是 ComfyUI 最常见的错误之一。

1. 模型下拉列表找不到文件

首先检查模型文件是否放在正确目录。

常见目录：

模型类型 目录
Checkpoint models/checkpoints/
LoRA models/loras/
VAE models/vae/
ControlNet models/controlnet/
CLIP Vision models/clip_vision/
Upscale Model models/upscale_models/
Diffusion Model models/diffusion_models/
Text Encoder models/text_encoders/

如果模型目录已经正确，可以尝试刷新模型列表或重启 ComfyUI。

如果使用了 extra_model_paths.yaml，还需要检查配置文件中的路径是否正确。

2. 模型文件损坏

如果模型文件下载不完整，可能出现加载失败。

可以检查：

  • 文件大小是否与下载页面一致。
  • 下载是否中断。
  • 文件是否被错误重命名。
  • 文件是否能够被正常识别。

必要时重新下载模型。

3. 模型架构不兼容

不同模型架构之间不能随意替换。

例如：

  • SD 1.5 Checkpoint 与 SDXL Checkpoint 不同。
  • SDXL LoRA 通常不能直接用于 SD 1.5。
  • FLUX 工作流需要对应的扩散模型、文本编码器和 VAE。
  • ControlNet 模型也需要与基础模型架构匹配。

如果工作流加载成功，但生成结果异常，模型架构不匹配也是需要检查的原因之一。

3.4、生成图片时显存不足怎么办？

显存不足是 ComfyUI 使用过程中非常常见的问题。

尤其是在运行 SDXL、FLUX、Qwen Image 等较大的模型时。

它通常表示当前任务需要的显存超过了可用显存。

1. 降低图片分辨率

分辨率越高，生成图片所需要的资源通常越多。

例如：

  • 512 × 512
  • 768 × 768
  • 1024 × 1024

对于传统 SD 1.5，可以先从 512 × 512 开始测试。

对于 SDXL、FLUX 等模型，应参考对应模型的推荐尺寸。

如果显存不足，先降低宽度和高度，再尝试生成。

2. 减少 Batch Size

3. 使用更轻量的模型

如果显存只有 4GB 或 6GB，运行大型模型可能非常困难。

可以考虑：

  • 使用 SD 1.5 等相对轻量的模型。
  • 使用适合当前显存的模型量化版本。
  • 减少同时加载的模型数量。
  • 避免运行复杂的多模型工作流。

量化模型是否可用取决于对应模型架构、节点和运行环境。

5. 使用分块 VAE 解码

如果采样已经完成，但在 VAE Decode 阶段显存不足，可以尝试分块解码。

部分工作流提供：

  • VAE Decode Tiled
  • Tiled VAE
  • 分块编码或解码节点

分块处理可以降低部分阶段的显存需求，但可能增加处理时间，也可能产生接缝等问题。

具体效果取决于工作流和节点实现。

3.5、生成过程中突然失败怎么办？

如果工作流可以正常启动，但运行到一半失败，需要根据失败阶段判断。

1. KSampler 阶段失败

可能原因：

  • 显存不足。
  • 模型不兼容。
  • 采样参数不适合当前模型。
  • 自定义节点异常。
  • PyTorch 或 CUDA 运行环境问题。

建议先降低分辨率、Batch Size，使用官方示例工作流测试。

2. VAE Decode 阶段失败

如果采样已经完成，但解码失败，重点检查：

  • VAE 是否正确。
  • 显存是否不足。
  • 图片分辨率是否过高。
  • 是否可以使用分块解码。

3. Save Image 阶段失败

如果图片已经生成，但无法保存，需要检查：

  • 输出目录是否存在。
  • 磁盘空间是否充足。
  • 文件路径是否正确。
  • 当前用户是否有写入权限。
  • 文件名前缀是否包含不适合当前系统的字符。

3.6、图片生成速度很慢怎么办？

生成速度慢不一定是故障。

可能与以下因素有关：

  • 模型规模较大。
  • 显存不足，发生模型卸载或换入换出。
  • 分辨率过高。
  • Steps 设置过多。
  • 使用 CPU 运行。
  • 自定义节点执行了额外处理。
  • 磁盘速度或系统内存不足。

建议按顺序检查：

  1. 确认 ComfyUI 是否使用 GPU。
  2. 检查显卡驱动和运行环境。
  3. 降低图片分辨率。
  4. 减少采样步数。
  5. 使用适合显存的模型。
  6. 检查是否有额外的图片处理节点。

如果使用 NVIDIA 显卡，可以通过任务管理器或显卡监控工具观察 GPU 使用情况。

不要仅根据 GPU 总利用率判断是否正常，还要关注显存占用和实际生成时间。

四、建立自己的故障排查清单

建议将下面的清单保存起来，遇到问题时逐项检查。

  • ComfyUI 是否正常启动？
  • 是否最近安装或更新了自定义节点？
  • 工作流是否存在缺失节点？
  • 模型文件是否放在正确目录？
  • 模型架构是否与工作流匹配？
  • Python 依赖是否安装到正确环境？
  • 是否存在显存不足？
  • 图片分辨率和 Batch Size 是否过高？
  • 输出目录是否存在？
  • 磁盘空间是否充足？
  • 错误日志是否提供了明确线索？

如果上述检查都无法解决问题，可以尝试使用官方简单工作流进行对比。

如果官方工作流可以正常运行，说明问题更可能出现在第三方节点、模型或原工作流中。

五、总结

ComfyUI 的错误虽然很多，但排查思路可以归纳为几个方向：

  • 启动失败：检查 Python 环境和自定义节点。
  • 节点缺失：检查节点安装和版本兼容。
  • 模型异常：检查模型路径、文件完整性和架构。
  • 生成失败：检查采样参数、节点和显存。
  • 保存失败：检查输出目录和磁盘空间。
  • 网络问题：检查监听地址、端口和防火墙。

最重要的是：先看日志，再定位问题，不要一遇到错误就重新安装整个 ComfyUI。

通过逐步排查，你会发现很多问题都能找到明确原因。
