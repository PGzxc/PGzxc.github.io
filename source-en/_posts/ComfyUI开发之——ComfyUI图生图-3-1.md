## 二、什么是图生图？

前面我们学习了 ComfyUI 文生图，通过提示词和随机噪声生成一张全新的图片。

图生图（Image to Image，简称 Img2Img）则不同：它不是从零开始生成，而是先加载一张已有图片，再将图片转换成模型可以处理的潜空间数据，经过采样和去噪后，生成一张新的图片。

简单理解：

- **文生图：** 根据提示词，从随机噪声开始生成图片。
- **图生图：** 根据已有图片和提示词，对原图进行重新生成。

例如，上传一张普通风景照，可以尝试将它转换成动漫风格、油画风格或电影质感；也可以在保留大致构图的基础上，改变画面的色彩、光线和氛围。

图生图常见用途：

- 图片风格转换：照片转动漫、油画、水彩等。
- 画面优化：调整光线、色彩、氛围和细节。
- 场景变化：在保留大致构图的情况下改变环境。
- 创意设计：根据草图或参考图生成新的作品。

需要注意，图生图主要用于整体画面重新生成。如果只想修改图片中的某个区域，例如更换衣服、修改背景或修复人物局部，通常更适合使用下一篇要介绍的局部重绘（Inpainting）。

## 三、图生图的基本工作流程

图生图与文生图的主要区别，是初始潜空间数据的来源不同。

文生图使用 Empty Latent Image 创建空白潜空间；图生图则使用 Load Image 加载原图，再通过 VAE Encode 将图片编码成潜空间数据。

基本流程如下：

```
Load Checkpoint
    ├── MODEL ───────────────────────┐
    ├── CLIP ── CLIP Text Encode ────┤
    └── VAE ── VAE Encode ──────────┤
                                    ↓
                                  KSampler
                                    ↓
                                VAE Decode
                                    ↓
                                 Save Image
```

其中，VAE Encode 负责将原图转换为潜空间数据，KSampler 根据提示词和 Denoise 参数重新采样，最后通过 VAE Decode 还原成图片。

## 四、搭建第一个图生图工作流

这里以 SD 1.5 模型为例。不同模型架构可能使用不同的加载和编码节点，本文先使用传统 Checkpoint 工作流理解基本原理。

### 4.1. 准备原图

准备一张 JPG 或 PNG 图片，可以使用自己的风景照、人物照，也可以使用 ComfyUI 自带的示例图片。

将图片放入：

```
ComfyUI/input/
```

也可以直接在 Load Image 节点中选择本地图片。

### 4.2. 添加所需节点

在画布中添加以下节点：

| 节点                       | 作用                   |
| -------------------------- | ---------------------- |
| Load Checkpoint            | 加载模型               |
| CLIP Text Encode（Prompt） | 编写正向提示词         |
| CLIP Text Encode（Prompt） | 编写负向提示词         |
| Load Image                 | 加载原始图片           |
| VAE Encode                 | 将原图编码成潜空间数据 |
| KSampler                   | 执行采样和去噪         |
| VAE Decode                 | 将潜空间数据还原为图片 |
| Save Image                 | 保存生成结果           |

### 4.3. 连接节点

按照下面的关系连接：

**模型与提示词：**

- Load Checkpoint 的 MODEL → KSampler 的 model。
- Load Checkpoint 的 CLIP → 正向 CLIP Text Encode 的 clip。
- Load Checkpoint 的 CLIP → 负向 CLIP Text Encode 的 clip。
- 正向 CLIP Text Encode 的 CONDITIONING → KSampler 的 positive。
- 负向 CLIP Text Encode 的 CONDITIONING → KSampler 的 negative。

**原图编码：**

- Load Image 的 IMAGE → VAE Encode 的 pixels。
- Load Checkpoint 的 VAE → VAE Encode 的 vae。
- VAE Encode 的 LATENT → KSampler 的 latent_image。

**图片输出：**

- KSampler 的 LATENT → VAE Decode 的 samples。
- Load Checkpoint 的 VAE → VAE Decode 的 vae。
- VAE Decode 的 IMAGE → Save Image 的 images。

与文生图相比，主要变化就是：不再使用 Empty Latent Image，而是使用 Load Image 和 VAE Encode 提供原图对应的潜空间数据。

### 4.4 设置提示词和参数

例如，加载一张普通风景照片，希望将它转换成具有电影质感的画面。

正向提示词：

```
beautiful landscape, cinematic lighting,
detailed environment, realistic photography,
soft sunlight, high quality
```

负向提示词：

```
blurry, low quality, distorted,
bad details, oversaturated
```

KSampler 可以先参考以下参数：

| 参数      | 示例值       |
| --------- | ------------ |
| Seed      | 固定一个数字 |
| Steps     | 20           |
| CFG       | 7            |
| Sampler   | Euler        |
| Scheduler | normal       |
| Denoise   | 0.5          |

这些参数只是 SD 1.5 的入门参考值，不同模型需要使用适合自身架构的工作流和参数。

完成连接后，点击 Queue Prompt 运行即可。

## 五、重点：Denoise 参数如何影响图生图？

Denoise 是图生图中非常重要的参数，决定原图在重新生成过程中受到多大程度的修改。

它的取值通常为 0～1。

可以先记住一个规律：

**Denoise 越低，越倾向于保留原图；Denoise 越高，越倾向于重新生成。**

下面是一个入门参考：

| Denoise  | 修改程度 | 大致效果                             |
| -------- | -------- | ------------------------------------ |
| 0.2～0.3 | 较低     | 保留原图较多，轻微调整               |
| 0.4～0.6 | 中等     | 保留部分结构，画面有明显变化         |
| 0.7～0.9 | 较高     | 画面变化较大，原图特征可能改变       |
| 1.0      | 很高     | 接近从噪声重新生成，原图影响明显减弱 |

注意：这些区间不是固定标准，也不代表 Denoise 0.5 就是保留 50% 的原图。实际效果还受到模型、采样器、Steps、提示词、图片内容等因素影响。

### 5.1. 低 Denoise：尽量保留原图

例如设置：

```
Denoise = 0.25
```

这种情况下，生成结果通常与原图比较接近，适合轻微调整画面风格、色彩和细节。

### 5.2. 中等 Denoise：保留结构并改变画面

例如设置：

```
Denoise = 0.5
```

原图的部分结构和构图通常能够保留，同时允许模型根据提示词重新生成更多细节。

适合尝试风格转换、画面优化等操作。

### 5.3. 高 Denoise：允许画面发生较大变化

例如设置：

```
Denoise = 0.8
```

模型会对原图进行更大幅度的重新生成，画面可能出现明显变化。

但人物面部、物体位置、构图等内容也可能发生改变。

### 5.4. Denoise 与 Steps 的关系

在传统 KSampler 中，Denoise 不仅影响修改幅度，还会影响采样过程使用的有效步数和起始噪声水平。

例如，Steps 设置为 20，Denoise 设置为 0.5，并不意味着简单地执行 10 步就一定能得到某种固定效果。

不同采样器和模型的实际表现也会有所差异。

因此，建议先固定其他参数，只调整 Denoise，通过实际生成结果理解它的作用。

## 六、实战：同一张图片生成不同效果

下面通过一个简单实验，观察 Denoise 对生成结果的影响。

### 6.1. 准备测试图片

选择一张风景照片，尽量选择主体清晰、构图简单的图片。

例如：

- 一张山水风景照。
- 一张普通建筑照片。
- 一张人物半身照片。

### 6.2. 固定其他参数

保持以下参数不变：

```
Steps = 20
CFG = 7
Sampler = Euler
Scheduler = normal
Seed = 固定数值
```

提示词也保持不变。

### 6.3. 分别测试 Denoise

依次设置：

```
第一次：Denoise = 0.25
第二次：Denoise = 0.50
第三次：Denoise = 0.75
```

每次运行后保存生成结果。

### 6.4. 对比生成效果

重点观察以下几个方面：

| 对比内容 | 观察重点                     |
| -------- | ---------------------------- |
| 原图构图 | 主体位置是否发生变化         |
| 图片风格 | 是否逐渐接近提示词描述的风格 |
| 画面细节 | 细节是否被重新生成           |
| 人物特征 | 面部和外观是否发生变化       |
| 背景环境 | 原有环境是否被改变           |

通过这次实验，就能直观理解 Denoise 参数与图片变化之间的关系。

## 七、图生图常见问题

### 7.1. 生成结果与原图几乎一样

可能原因：

- Denoise 设置过低。
- 提示词对画面变化的描述不够明确。
- 模型对原图保留程度较高。

可以尝试逐步提高 Denoise，或者调整提示词。

### 7.2. 生成结果与原图差别太大

可能原因：

- Denoise 设置过高。
- 提示词与原图内容差异较大。
- 模型无法很好地理解原图中的主体。

可以降低 Denoise，并尽量使用符合原图内容的提示词。

### 7.3. 生成结果出现黑图或颜色异常

重点检查：

- VAE 是否与当前模型匹配。
- VAE Encode 和 VAE Decode 是否使用了正确的 VAE。
- 模型文件是否完整。
- 当前工作流是否适用于所加载的模型。

尤其要注意，不同模型架构不能随意混用 VAE 和节点配置。

### 7.4. 图片比例或尺寸发生变化

检查 Load Image 后面的图片尺寸处理节点。

如果需要调整尺寸，可以根据工作流添加 Image Scale 或其他 Resize 节点。

注意保持合理的宽高比例，并根据模型要求选择合适的分辨率。随意拉伸图片可能造成主体变形。

## 八、图生图与局部重绘有什么区别？

图生图可以对整张图片进行重新生成，但如果只想修改某个区域，就需要使用更精细的控制方式。

例如：

| 需求                       | 推荐方式 |
| -------------------------- | -------- |
| 将照片转换成动漫风格       | 图生图   |
| 改变整张图片的色彩和氛围   | 图生图   |
| 在保留构图的情况下改变画面 | 图生图   |
| 只更换人物衣服             | 局部重绘 |
| 只修改人物背景             | 局部重绘 |
| 修复照片中的某个缺陷       | 局部重绘 |

图生图更适合整体调整，局部重绘则可以通过遮罩指定需要修改的区域，尽量保留其他部分。

## 九、本篇总结

这一篇学习了 ComfyUI 图生图的基本原理和工作流。

需要掌握的知识点：

1. 图生图是根据已有图片重新生成，而不是完全从零开始。
2. Load Image 负责加载原图。
3. VAE Encode 将原图转换为潜空间数据。
4. KSampler 根据提示词和参数执行重新采样。
5. Denoise 控制原图受到的修改程度。
6. Denoise 越低，通常越容易保留原图；越高，画面变化通常越大。

建议自己准备一张照片，分别使用 0.25、0.5 和 0.75 进行测试，保存结果并对比。
