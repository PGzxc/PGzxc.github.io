```
上一篇，我们学习了正向提示词、负向提示词和关键词权重，

但即使提示词完全相同，生成出来的图片也可能不同。
```

## 二、先认识 KSampler 节点

在上一篇搭建的 SD 1.5 文生图工作流中，找到 KSampler 节点。

它通常包含以下参数：

|   参数    |            作用            |
| :-------: | :------------------------: |
|   Seed    |      控制初始随机噪声      |
|   Steps   |        控制采样步数        |
|    CFG    | 控制模型对提示词的遵循程度 |
|  Sampler  |        选择采样算法        |
| Scheduler |  控制采样过程中的噪声调度  |
|  Denoise  |        控制去噪强度        |

其中，Seed、Steps、CFG、Sampler 和 Scheduler 是本篇重点。

## 三 KSampler 节点详解

### 3.1、Seed：随机种子

Seed（随机种子）用于控制生成过程中的初始随机状态。

可以简单理解为：模型开始生成图片前，需要有一个初始的随机噪声，而 Seed 可以帮助确定这份随机噪声。

例如：

```
Seed: 123456789
```

在模型、提示词、尺寸、采样器和其他参数都不变的情况下，使用相同 Seed，通常可以得到相同或高度一致的生成结果。

#### 1. 固定 Seed 有什么用？

假设我们使用同一段提示词：

```
a beautiful girl, long hair,
white dress, flower garden,
realistic photography
```

第一次生成：

```
Seed: 123456789
```

第二次仍然使用：

```
Seed: 123456789
```

如果其他条件也保持一致，生成结果通常可以复现。

这对于测试参数非常有帮助。

例如，想比较 CFG=5 和 CFG=8 的区别，就可以固定 Seed，只修改 CFG。

#### 2. 随机 Seed 和固定 Seed

在 ComfyUI 中，KSampler 的 Seed 通常还会配合生成后的控制选项使用，例如：

- fixed：保持种子不变。
- increment：每次执行后递增。
- decrement：每次执行后递减。
- randomize：每次执行时随机生成新的种子。

不同版本或节点可能提供不同选项。

建议：

- 调试提示词时：固定 Seed。
- 想尝试不同构图时：使用随机 Seed。
- 批量生成多张图片时：可以递增 Seed。

**记住：Seed 不代表图片质量。** 数值大不一定更好，数值小也不一定更差。

### 3.2、Steps：采样步数

Steps 表示采样过程中执行的迭代步数。

简单来说，模型需要经过一定次数的计算，逐步将初始噪声转换为符合提示词的图像。

Steps 越高，计算量通常越大，但不代表图片质量一定越好。

#### 1. 不同步数有什么区别？

以 SD 1.5 为例，可以先参考以下测试范围：

| Steps |               特点               |
| :---: | :------------------------------: |
|  10   |      生成较快，细节可能不足      |
|  20   |          常见入门测试值          |
|  30   |       可以观察更多细节变化       |
|  40   | 计算时间增加，效果不一定继续提升 |
|  50   | 需要结合模型和采样器判断是否值得 |

这些数值只是测试参考，不是所有模型的最佳设置。

#### 2. Steps 越高越好吗？

不一定。

当采样步数达到一定程度后，继续增加 Steps，可能只会增加生成时间，图片质量却没有明显改善。

某些采样器和模型在较少步数下就能得到不错的结果；另一些模型则需要不同的步数配置。

建议从模型推荐参数开始，再逐步测试。

### 3.3、CFG：提示词引导强度

CFG 全称 Classifier-Free Guidance，可以理解为模型遵循提示词的引导强度。

它影响生成结果在多大程度上受到正向和负向条件的引导。

在经典 SD 1.5 工作流中，CFG 是非常常见的调节参数。

#### 1. CFG 数值有什么区别？

以 SD 1.5 为例，可以参考：

|   CFG   |            大致特点            |
| :-----: | :----------------------------: |
|  3～5   |  引导较弱，生成结果可能更自由  |
|  6～8   |          常见测试范围          |
|  9～12  |   引导较强，可能更强调提示词   |
| 12 以上 | 需要谨慎测试，可能出现过度引导 |

例如，我们输入：

```
a woman wearing a red dress,
standing in a garden
```

如果 CFG 较低，模型可能不会严格体现所有描述。

如果 CFG 较高，模型可能更努力地贴合提示词，但过高也可能带来颜色失真、画面不自然等问题。

#### 2. CFG 应该设置多少？

对于 SD 1.5，可以先从 7 左右开始测试。

如果发现模型对提示词响应较弱，可以适当提高；如果图片出现过度饱和或不自然的情况，可以尝试降低。

注意：不同模型对 CFG 的适用范围不同。例如部分 FLUX 工作流使用的引导方式和参数设置就与传统 SD 1.5 有明显区别，不应直接套用 SD 1.5 的经验。

### 3.4、Sampler：采样器

Sampler 是采样算法的选择。

不同采样器采用不同的计算方式，将初始噪声逐步转换成图像。

在 ComfyUI 的 KSampler 中，常见选项包括：

|    采样器    |           简要说明           |
| :----------: | :--------------------------: |
|    Euler     | 常见基础采样器，适合入门测试 |
|   Euler a    | 带有随机性特征的 Euler 变体  |
|     Heun     |    使用不同的数值求解方式    |
|   DPM++ 2M   |      常见的高阶采样方法      |
| DPM++ 2M SDE | 引入随机微分方程相关采样方式 |
|     DDIM     |     经典扩散模型采样方法     |
|     LMS      |   基于线性多步方法的采样器   |

不同采样器在生成速度、细节表现、稳定性和适合的步数方面可能存在差异。

#### 1. Euler 和 Euler a 有什么区别？

Euler 是一种常见的采样算法，适合用于理解和测试基础工作流。

Euler a 中的 a 表示 ancestral，通常会在采样过程中引入额外随机性。

因此，即使其他条件相同，两者生成结果也可能存在明显差异。

#### 2. DPM++ 2M 和 DPM++ 2M SDE 有什么区别？

DPM++ 2M 是常见的多步采样方法。

DPM++ 2M SDE 则采用了不同的随机采样机制。

两者并不是简单的质量高低关系，实际表现还取决于模型、Steps、Scheduler 等因素。

**入门建议：**

先使用 Euler 熟悉工作流，再尝试 DPM++ 2M 和 DPM++ 2M SDE，比较生成效果。

不要一开始就纠结哪一种采样器最好。

### 3.5、Scheduler：噪声调度器

如果说 Sampler 决定了采用什么算法进行采样，那么 Scheduler 则负责安排采样过程中不同阶段使用的噪声水平。

它会影响采样过程中噪声强度的变化方式。

在 ComfyUI 中，常见的 Scheduler 包括：

|  Scheduler   |         简要说明          |
| :----------: | :-----------------------: |
|    normal    |  常见的基础噪声调度方式   |
|    karras    | 使用 Karras 噪声调度方案  |
| exponential  |    指数形式的噪声调度     |
|    simple    |    简化的噪声调度方式     |
| ddim_uniform | DDIM 风格的均匀时间步调度 |

不同 Scheduler 与不同 Sampler 组合后，生成结果可能有所不同。

例如：

```
Sampler: Euler
Scheduler: normal
```

也可以尝试：

```
Sampler: DPM++ 2M
Scheduler: karras
```

注意，并不是所有 Sampler 和 Scheduler 的组合都具有相同的适用性。某些组合在特定模型上表现更好，应该以模型推荐配置和实际测试为准。

### 3.6、Denoise：去噪强度

虽然本篇重点是五个采样参数，但 Denoise 也非常重要。

它控制采样过程中的去噪强度。

在经典文生图工作流中，通常设置为：

```
Denoise: 1.0
```

因为文生图需要从初始噪声开始生成完整图片。

而在图生图工作流中，Denoise 的作用就更加明显。

例如：

| Denoise |            大致效果            |
| :-----: | :----------------------------: |
|   0.2   |   保留原图较多，只做轻微修改   |
|   0.4   |  在保留原图基础上进行一定变化  |
|   0.6   |      允许较明显的画面变化      |
|   0.8   |    原图特征可能发生较大改变    |
|   1.0   | 去噪强度最大，可能接近重新生成 |

这些只是帮助理解的参考值，实际变化取决于模型、输入图片和工作流。

后续学习图生图时，我们会专门介绍 Denoise 的实际用法。

## 四、实战：对比不同采样参数的生成效果

了解参数后，最好的学习方式就是自己动手测试。

我们继续使用上一篇的 SD 1.5 文生图工作流。

### 4.1. 固定基础条件

先在正向提示词中输入：

```
a beautiful young woman,
long black hair, wearing a white dress,
standing in a flower garden,
soft natural sunlight,
realistic photography
```

负向提示词：

```
blurry, low quality,
bad anatomy, deformed hands,
extra fingers, watermark
```

固定以下参数：

|   参数    |   设置    |
| :-------: | :-------: |
| 图片尺寸  | 512 × 512 |
|   Seed    | 123456789 |
|   Steps   |    20     |
|    CFG    |     7     |
|  Sampler  |   Euler   |
| Scheduler |  normal   |
|  Denoise  |    1.0    |

先生成一张图片，作为后续对比的基准。

### 4.2. 测试 Steps

保持其他参数不变，分别测试：

```
Steps: 10
Steps: 20
Steps: 30
Steps: 40
```

观察生成速度、细节和整体效果。

### 4.3. 测试 CFG

保持其他参数不变，分别测试：

```
CFG: 4
CFG: 6
CFG: 7
CFG: 9
CFG: 11
```

观察人物服装、场景和整体画面是否更加贴合提示词。

### 4.4 测试 Sampler

固定 Seed、Steps、CFG 等参数，分别测试：

```
Euler
Euler a
DPM++ 2M
DPM++ 2M SDE
```

观察不同采样器带来的画面差异。

### 4.5. 测试 Scheduler

选择合适的 Sampler，再分别测试：

```
normal
karras
exponential
simple
```

观察不同调度方式对生成结果的影响。

> 实验时，每次只修改一个参数，其他参数保持不变。这样才能更容易判断究竟是哪项设置影响了生成结果。

## 五、入门参数怎么选？

如果目前主要使用 SD 1.5，可以先从下面这组参数开始：

|   参数    |  建议起点  |
| :-------: | :--------: |
|   Seed    | 固定或随机 |
|   Steps   |     20     |
|    CFG    |     7      |
|  Sampler  |   Euler    |
| Scheduler |   normal   |
|  Denoise  |    1.0     |

这是一组便于入门和比较的基础配置，并不是所有模型、提示词和图片尺寸下的最佳参数。

当你熟悉这些参数后，再根据模型推荐配置进行调整。

## 六、总结

这一篇，我们学习了 ComfyUI 文生图中的五个核心采样参数，以及 Denoise 的基本作用。

- Seed：控制初始随机状态，方便复现和比较结果。
- Steps：控制采样步数，影响计算量和生成效果。
- CFG：控制模型对提示词的引导强度。
- Sampler：选择采样算法。
- Scheduler：控制采样过程中的噪声调度。
- Denoise：控制去噪强度，图生图中尤其重要。

对于初学者，建议先固定 Seed，使用 Euler、normal、Steps 20、CFG 7 进行测试。

每次只调整一个参数，观察生成结果，逐步建立自己的参数经验。
