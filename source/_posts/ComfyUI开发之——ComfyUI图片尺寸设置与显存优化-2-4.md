## 一、概述

```
上一篇，我们学习了 Seed、Steps、CFG、Sampler 和 Scheduler 等采样参数，知道了如何通过调整参数影响图片生成效果。

但在实际使用 ComfyUI 时，还会遇到一个问题：
图片尺寸越大，生成过程越容易变慢，甚至出现显存不足（Out of Memory，简称 OOM）。

尤其是使用本地电脑运行 AI 图像模型时，显卡显存、系统内存和模型大小都会影响生成体验。

这篇文章就介绍图片尺寸的设置方法、显存占用的影响因素，以及电脑配置有限时可以采用的优化方案。
```

## 二、图片尺寸

### 2.1、图片尺寸为什么这么重要？

在 ComfyUI 中，图片尺寸通常由 Empty Latent Image 节点设置。

例如：

```
width: 512
height: 512
batch_size: 1
```

表示生成一张 512×512 的图片。

如果修改为：

```
width: 1024
height: 1024
batch_size: 1
```

生成图片的宽度和高度都增加了一倍，但总像素数量变成了原来的四倍。

| 图片尺寸  | 总像素数量 | 相对像素量 |
| --------- | ---------- | ---------- |
| 512×512   | 262,144    | 1 倍       |
| 768×768   | 589,824    | 2.25 倍    |
| 1024×1024 | 1,048,576  | 4 倍       |
| 1536×1536 | 2,359,296  | 9 倍       |
| 2048×2048 | 4,194,304  | 16 倍      |

这意味着图片尺寸增加后，模型需要处理更多的图像数据，计算量和内存需求通常也会增加。

特别是对于使用注意力机制的模型，分辨率提高可能带来明显的显存压力。

需要注意：显存占用并不完全按照像素数量成比例增长，还受到模型结构、注意力实现、批量数量、精度和工作流节点等因素影响。

### 2.2、不同模型应该使用多大分辨率？

不同图像模型的训练分辨率和推荐尺寸并不一样，不能所有模型都使用同一套参数。

下面是一些常见的入门参考：

| 模型类型   | 常见测试尺寸         | 说明                       |
| ---------- | -------------------- | -------------------------- |
| SD 1.5     | 512×512              | 经典基础测试尺寸           |
| SD 1.5     | 512×768、768×512     | 适合尝试竖图和横图         |
| SDXL       | 1024×1024            | 常见基础测试尺寸           |
| FLUX       | 依据模型与工作流推荐 | 通常需要更多计算资源       |
| Qwen Image | 依据模型与工作流推荐 | 需要关注模型自身的尺寸要求 |

这些是常见参考，不是严格限制。

例如，SD 1.5 可以生成 1024×1024 的图片，但直接使用较高分辨率可能出现构图异常、人物重复或细节不稳定等问题。

对于 SD 1.5，比较常见的做法是：

1. 先生成 512×512 的基础图片。
2. 确认人物和构图符合要求。
3. 再通过高清放大或二次处理提高分辨率。

SDXL 则通常以 1024×1024 作为常见的基础尺寸。

对于 FLUX、Qwen Image 等模型，建议优先参考模型说明和对应工作流，不要直接套用 SD 1.5 的尺寸经验。

### 2.3、图片尺寸应该如何设置？

在经典文生图工作流中，找到 Empty Latent Image 节点。

通常可以调整三个参数：

- width：图片宽度。
- height：图片高度。
- batch_size：一次生成的图片数量。

#### 1. 宽度和高度

如果要生成不同方向的图片，可以参考：

| 图片方向 | SD 1.5 入门尺寸 |
| -------- | --------------- |
| 正方形   | 512×512         |
| 竖版     | 512×768         |
| 横版     | 768×512         |

例如，制作手机壁纸或人物全身照，可以尝试竖版尺寸。

制作风景图片或横向封面，可以尝试横版尺寸。

#### 2. Batch Size：批量生成数量

Batch Size 表示一次处理多少张图片。

例如：

```
width: 512
height: 512
batch_size: 1
```

表示一次生成一张。

如果修改为：

```
width: 512
height: 512
batch_size: 4
```

则表示一次生成四张。

Batch Size 增加后，通常会增加显存和内存需求。

如果电脑显存比较有限，建议先设置为 1，需要多张图片时再通过多次执行或其他批量工作流完成。

#### 3. 图片尺寸不是随便设置的

部分模型和工作流对图片宽高有特定要求。

例如，传统 Stable Diffusion 模型通常使用能够被 8 整除的尺寸；某些新架构模型则可能有不同的尺寸对齐要求。

因此，设置尺寸时要注意：

- 优先使用模型推荐尺寸。
- 不要一开始就设置特别大的分辨率。
- 尽量保持宽高比例符合实际需求。
- 遇到尺寸错误时，检查模型和节点的尺寸限制。

## 三、显存优化

### 3.1、ComfyUI 为什么会占用大量显存？

显存（VRAM）是显卡上的高速内存，用于存放模型参数、计算数据和中间结果。

ComfyUI 运行图像模型时，显存主要用于以下几个方面：

**1. 模型权重**

加载 Checkpoint 或其他模型时，需要占用一定显存。

模型越大，通常需要的存储空间越多。

**2. 中间计算数据**

在采样过程中，模型会产生大量中间数据。

这些数据与图片尺寸、模型结构、批量数量等因素有关。

**3. VAE 解码**

KSampler 完成采样后，还需要通过 VAE Decode 将 LATENT 转换为普通图片。

分辨率较高时，VAE 解码也可能带来额外的显存压力。

**4. 其他节点和模型**

如果工作流中同时使用 LoRA、ControlNet、IP-Adapter、高清放大模型等，也可能进一步增加资源占用。

因此，不能只根据模型文件大小判断电脑能否运行。

模型能够加载，不代表一定能顺利完成整个工作流。

### 3.2、显存不足时有哪些解决方法？

如果生成图片时出现 CUDA out of memory、显存不足或程序异常退出，可以按照下面的顺序排查。

#### 1. 降低图片分辨率

这是最直接的方法。

例如，将：

```
1024 × 1024
```

调整为：

```
512 × 512
```

如果仍然不足，可以继续降低分辨率，先确认基础工作流能够正常运行。

#### 2. 降低 Batch Size

将：

```
batch_size: 4
```

修改为：

```
batch_size: 1
```

对于显存有限的电脑，建议优先使用单张生成。

#### 3. 选择更轻量的模型

如果使用的是大型模型，可以考虑更小的模型或经过合理量化的版本。

例如：

- SD 1.5：相对轻量，适合入门。
- SDXL：通常比 SD 1.5 需要更多资源。
- FLUX：不同版本和量化方式的资源需求差异较大。
- Qwen Image：应根据具体模型版本和运行方式评估资源需求。

模型越小不一定代表效果越差，但要根据具体任务选择。

#### 4. 使用低显存运行模式

ComfyUI 支持不同的显存管理策略，可以根据电脑配置选择。

常见启动参数包括：

| 参数                     | 作用                                               |
| ------------------------ | -------------------------------------------------- |
| `--lowvram`              | 尝试降低显存使用，适合显存较小的显卡               |
| `--normalvram`           | 使用普通显存管理模式                               |
| `--highvram`             | 尽可能将模型保持在显存中，适合显存较充足的设备     |
| `--cpu`                  | 使用 CPU 运行模型，速度通常较慢                    |
| `--force-fp16`           | 尝试强制使用 FP16 精度，具体兼容性需结合模型和设备 |
| `--disable-smart-memory` | 禁用部分智能显存管理策略，可能改变内存调度方式     |

这些参数的实际效果与 ComfyUI 版本、显卡、驱动和模型有关。

不要一次添加所有参数。建议先正常启动，出现显存问题后再逐项尝试。

#### 5. 使用 VAE 分块解码

如果采样已经完成，但在 VAE Decode 阶段出现显存不足，可以考虑使用分块 VAE 解码。

ComfyUI 提供了相应的分块 VAE 解码节点，具体名称可能因版本和节点包不同而有所区别。

分块解码会将图片拆成多个区域处理，降低单次解码的显存需求。

但需要注意，分块处理可能带来额外耗时，部分设置下还需要注意分块边缘的拼接效果。

#### 6. 关闭不必要的程序

运行 ComfyUI 前，可以关闭：

- 占用大量显存的游戏。
- 其他 AI 图像生成程序。
- 不必要的视频剪辑软件。
- 占用大量 GPU 资源的应用。

同时检查系统内存是否充足。

显存不足和系统内存不足是两个不同的问题，不能混为一谈。

### 3.3、ComfyUI 常见启动参数怎么使用？

如果使用 Windows 便携版或手动安装版，可以通过启动脚本传入参数。

例如，便携版目录中可能存在：

```
run_nvidia_gpu.bat
run_cpu.bat
```

可以通过编辑对应的启动脚本，增加启动参数。

例如：

```
python main.py --lowvram
```

如果需要局域网访问，也可以根据实际需求组合：

```
python main.py --lowvram --listen 0.0.0.0 --port 8188
```

这里：

- `--lowvram`：尝试降低显存使用。
- `--listen 0.0.0.0`：允许局域网内其他设备访问。
- `--port 8188`：指定服务端口。

如果使用 ComfyUI Desktop，启动参数的设置方式可能与便携版不同，应以当前版本的设置界面和官方说明为准。

另外，开启局域网访问时，应确保只允许可信设备连接，不要直接将 ComfyUI 服务暴露到公网。

### 3.4、显卡配置有限，应该怎么选择方案？

不同显卡的显存容量和计算能力差异很大。

可以先根据显存容量做一个粗略判断：

| 显存容量    | 使用建议                                         |
| ----------- | ------------------------------------------------ |
| 2GB～4GB    | 优先考虑轻量模型、低分辨率和 CPU/显存优化方案    |
| 6GB         | 可以尝试部分轻量模型，注意控制分辨率和批量数量   |
| 8GB         | 可以运行更多常见图像工作流，但大型模型仍可能受限 |
| 12GB        | 可尝试更高分辨率和部分较大型模型                 |
| 16GB 及以上 | 选择空间更大，但仍需要考虑模型结构和工作流复杂度 |

这只是粗略参考，不代表某个模型一定能在对应显存下运行。

实际还要看模型精度、量化方式、系统占用、显存管理策略，以及是否同时加载多个模型。

如果显存不足，也可以考虑云端 GPU 或远程 ComfyUI 服务。

## 四、实战：制作一套适合自己电脑的生成参数

下面以 SD 1.5 为例，建立一套基础测试配置。

在 Empty Latent Image 中设置：

```
width: 512
height: 512
batch_size: 1
```

在 KSampler 中设置：

```
steps: 20
cfg: 7
sampler_name: euler
scheduler: normal
denoise: 1.0
```

先使用这套配置完成一次生成。

### 4.2. 测试更高分辨率

依次尝试：

```
512 × 512
512 × 768
768 × 768

```

每次观察：

- 图片是否正常生成。
- 显存占用是否明显增加。

- 是否出现显存不足。

如果某个尺寸无法正常运行，就回到上一个可用尺寸。

## 五、总结

这一篇主要学习了 ComfyUI 图片尺寸和显存优化：

- 图片尺寸越大，通常需要处理更多数据。
- Batch Size 越大，通常需要更多显存。
- 不同模型有不同的推荐分辨率。
- 显存不足时，可以降低分辨率、减少批量数量、选择轻量模型。
- `--lowvram` 等启动参数可以辅助调整显存管理方式。
- VAE 分块解码可以缓解部分解码阶段的显存压力。
- 最终配置应通过实际测试确定。

对于初学者，建议先从 SD 1.5 的 512×512、Batch Size 1 开始，确保基础工作流稳定运行，再逐步提高分辨率。
