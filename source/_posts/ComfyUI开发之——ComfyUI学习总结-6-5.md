## 二、回顾 ComfyUI 的学习路线

整个系列分为六个阶段。

|             阶段             |                 学习内容                 |          核心目标           |
| :--------------------------: | :--------------------------------------: | :-------------------------: |
|      第一阶段：基础入门      |      安装、目录、界面、模型、工作流      | 理解 ComfyUI 的基本使用方式 |
|  第二阶段：文生图与核心参数  |      提示词、采样器、尺寸、模型管理      |       独立完成文生图        |
|   第三阶段：图像生成与控制   | 图生图、局部重绘、放大、LoRA、ControlNet | 掌握常见图片生成和修改方法  |
|    第四阶段：工作流与扩展    |  节点、工作流导入、自定义节点、故障排查  |  能够修改和管理复杂工作流   |
|  第五阶段：AI 图片处理实战   |    换背景、服装修改、照片修复、证件照    | 将 ComfyUI 用于实际图片处理 |
| 第六阶段：进阶应用与项目集成 |    视频生成、本地 API、Python 自动化     |   将 ComfyUI 接入其他应用   |

学习过程中，建议不要只关注生成效果，还要理解每个工作流的输入、输出、节点依赖和参数配置。

例如，一个图生图工作流不仅要知道如何点击运行，还应该能够回答：

1. 输入图片来自哪个节点？
2. 提示词在哪个节点修改？
3. 哪个参数控制原图保留程度？
4. 使用了什么模型和 VAE？
5. 最终图片保存到哪里？
6. 如果出现报错，应该从哪里排查？

能够回答这些问题，才说明真正理解了工作流。

## 三、操作流程

### 3.1、建立自己的模型库

模型是 ComfyUI 生成图片和视频的基础。

随着学习深入，模型文件会越来越多。如果没有统一管理，很容易出现模型重复下载、路径混乱、版本不清楚等问题。

#### 1. 认识常见模型类型

|     模型类型     |            主要用途            |          常见目录          |
| :--------------: | :----------------------------: | :------------------------: |
|    Checkpoint    |        基础图像生成模型        |   `models/checkpoints/`    |
|       VAE        |  图像与潜空间之间的编码、解码  |       `models/vae/`        |
|       LoRA       |    调整人物、风格或画面特征    |      `models/loras/`       |
|    ControlNet    | 根据姿势、边缘、深度等控制生成 |    `models/controlnet/`    |
|       CLIP       |         文本提示词编码         |       `models/clip/`       |
|   CLIP Vision    |          图像特征编码          |   `models/clip_vision/`    |
|  Upscale Model   |       图片放大和细节增强       |  `models/upscale_models/`  |
| Diffusion Models |   部分架构使用的扩散模型文件   | `models/diffusion_models/` |

以上是常见目录示例，实际目录和模型加载方式会随模型架构、ComfyUI 版本及节点扩展有所不同。

例如，SD 1.5、SDXL 和 FLUX 的模型组件及工作流并不完全相同，不能只根据文件扩展名判断模型是否兼容。

#### 2. 推荐的模型管理方式

可以按照用途对模型进行分类：

```
ComfyUI/
└── models/
    ├── checkpoints/
    │   ├── sd15/
    │   └── sdxl/
    │
    ├── diffusion_models/
    ├── text_encoders/
    ├── vae/
    ├── loras/
    │   ├── portrait/
    │   ├── style/
    │   └── character/
    │
    ├── controlnet/
    ├── clip_vision/
    └── upscale_models/
```

这里的子目录只是管理建议，ComfyUI 是否能扫描到模型，还要看对应加载器和当前版本的目录配置。

如果使用多个 ComfyUI 环境，也可以通过模型搜索路径配置共享模型目录，减少重复占用磁盘空间。

#### 3. 建立模型信息清单

建议每下载一个模型，都记录基本信息。

| 项目     | 记录内容                        |
| -------- | ------------------------------- |
| 模型名称 | 实际模型文件名                  |
| 模型类型 | Checkpoint、LoRA、ControlNet 等 |
| 模型架构 | SD 1.5、SDXL、FLUX 等           |
| 文件大小 | 模型占用空间                    |
| 下载来源 | 官方页面或可信模型发布页面      |
| 适用场景 | 人像、风景、修复、放大等        |
| 使用说明 | 触发词、推荐参数、兼容要求      |

这样后续查找模型、迁移环境和复现工作流都会更加方便。

下载模型时，优先选择可信来源，检查模型许可、使用限制和文件完整性，不要随意运行来源不明的模型附带脚本。

### 3.2、建立自己的工作流库

模型解决的是生成能力问题，工作流解决的是如何组织这些能力。

同一个模型，通过不同工作流可以完成不同任务。

例如：

- 文生图：根据提示词生成图片。
- 图生图：根据原图生成新图片。
- 局部重绘：只修改图片指定区域。
- ControlNet：控制姿势、边缘和深度。
- 图片放大：提高输出分辨率。
- 图片修复：改善旧照片质量。

如果每次都从空白画布重新搭建工作流，会浪费大量时间。

因此，建议建立自己的工作流库。

#### 1. 推荐的工作流分类

```
My-ComfyUI-Workflows/
│
├── 01-文生图/
│   ├── 基础文生图.json
│   ├── SDXL文生图.json
│   └── FLUX文生图.json
│
├── 02-图生图/
│   ├── 基础图生图.json
│   └── 风格转换.json
│
├── 03-局部重绘/
│   ├── 人物局部修改.json
│   └── 背景修改.json
│
├── 04-人物一致性/
│   ├── IP-Adapter.json
│   └── InstantID.json
│
├── 05-图片修复/
│   ├── 老照片修复.json
│   └── 图片高清放大.json
│
├── 06-证件照/
│   ├── 背景替换.json
│   └── 证件照处理.json
│
├── 07-视频生成/
│   └── 图片转视频.json
│
└── 08-API自动化/
    └── API文生图.json
```

建议同时保存两种文件：

- 普通工作流 JSON：用于在 ComfyUI 界面中打开和编辑。
- API 格式 JSON：用于 Python 程序或其他客户端调用。

不要只保存最终生成的图片，工作流也是非常重要的项目资料。

#### 2. 为每个工作流建立说明文档

每个工作流建议配套一份说明：

```
# 工作流名称

## 主要用途
说明这个工作流能够完成什么任务。

## 模型要求
- 基础模型：
- VAE：
- LoRA：
- 其他模型：

## 自定义节点
- 节点名称：
- 安装来源：

## 输入参数
- 图片：
- 提示词：
- Seed：
- 图片尺寸：

## 输出结果
- 输出类型：
- 保存目录：

## 使用步骤
1. 导入工作流。
2. 检查模型。
3. 修改参数。
4. 点击运行。

## 注意事项
记录模型兼容性、显存要求和常见问题。
```

这样，即使过几个月重新使用某个工作流，也不需要重新研究一遍。

#### 3. 工作流版本管理

工作流修改后，建议保留历史版本。

例如：

```
portrait_v1.json
portrait_v2.json
portrait_v3.json
```

或者使用 Git 管理工作流文件和说明文档。

这样可以比较不同版本的节点变化，必要时也能恢复之前的配置。

注意，模型文件通常比较大，不建议直接将大量模型文件提交到普通 Git 仓库。可以使用独立模型目录或 Git LFS 等方式管理。

### 3.3、建立一套稳定的 ComfyUI 使用流程

实际使用时，建议按照固定流程操作。

**第一步：明确生成目标。**

先判断任务属于哪种类型：

- 从文字生成图片。
- 根据原图修改图片。
- 修改指定区域。
- 保持人物或物体特征。
- 图片修复或放大。
- 图片转视频。

**第二步：选择合适的模型。**

根据任务选择模型架构和配套组件，不要为了追求效果而盲目下载大型模型。

**第三步：选择或搭建工作流。**

优先使用已经测试成功的工作流，再根据实际需求修改节点和参数。

**第四步：先小规模测试。**

先使用较低分辨率、较少生成数量验证效果，确认模型和节点都正常后再提高参数。

**第五步：保存结果和参数。**

保存生成图片、提示词、Seed、模型信息和工作流文件。

**第六步：整理和复盘。**

效果好的工作流放入自己的工作流库，记录适用场景和参数范围。

这套流程能够减少重复劳动，也有助于形成自己的 AI 图片处理经验。

## 四、个人项目案例：将 ComfyUI 用于实际应用

学习 ComfyUI 的最终目的，不只是生成漂亮图片，而是把它应用到真实需求中。

结合前面学习的图片处理技术，可以考虑以下项目。

### 4.1 案例一：AI 证件照制作

证件照是一个比较适合练习 ComfyUI 的项目。

基本流程：

```
上传或拍摄照片
       │
       ▼
人物抠图
       │
       ▼
背景替换
       │
       ▼
服装调整（可选）
       │
       ▼
人像位置与尺寸调整
       │
       ▼
裁剪与输出
       │
       ▼
生成证件照
```

可以使用人物分割、背景合成、局部重绘和图片调整等技术。

不过，证件照有严格的规范要求，不能只依赖 AI 生成结果。

尤其要注意：

- 保持本人真实面部特征。
- 避免改变五官、脸型和身份特征。
- 背景颜色符合目标用途要求。
- 头部比例、肩部位置和裁剪尺寸符合规范。
- 输出分辨率和文件格式符合办理机构要求。

如果用于正式证件，应以相关机构的最新照片规范为准，AI 生成后还需要进行人工检查。

### 4.2 案例二：老人照片修复与纪念照片制作

老照片修复也是比较有实际价值的应用场景。

常见处理需求：

- 修复照片划痕和破损。
- 改善模糊和噪点。
- 调整亮度和对比度。
- 适度增强人物面部细节。
- 更换背景或调整服装。

基本流程：

```
上传老照片
     │
     ▼
图片质量检查
     │
     ▼
划痕与破损修复
     │
     ▼
人脸细节增强
     │
     ▼
背景或服装调整（可选）
     │
     ▼
人工检查
     │
     ▼
保存修复结果
```

这类任务需要特别注意人物身份保持。

老照片中的人脸信息可能已经不完整，AI 修复有时会生成原图中不存在的五官细节。因此，应尽量保留原始面部特征，不要将 AI 补全的细节误认为真实历史信息。

对于纪念照片，也应保留原始照片，避免覆盖或丢失原始资料。

### 4.3 案例三：本地 AI 图片处理客户端

前面第 28 篇已经学习了 ComfyUI API，第 29 篇又实现了 Python 批量处理。

接下来就可以把这些能力封装成一个客户端。

客户端主要负责：

- 选择图片。
- 输入提示词。
- 选择处理类型。
- 设置图片尺寸和生成参数。
- 提交任务。
- 显示任务进度。
- 展示和保存生成结果。

整体架构可以设计为：

```
┌──────────────────────┐
│      客户端           │
│                      │
│  图片选择 / 参数设置  │
│  任务列表 / 结果展示  │
└──────────┬───────────┘
           │ HTTP / WebSocket
           ▼
┌──────────────────────┐
│    Python 服务层      │
│                      │
│  任务管理 / 参数处理  │
│  文件管理 / 结果返回  │
└──────────┬───────────┘
           │ ComfyUI API
           ▼
┌──────────────────────┐
│       ComfyUI        │
│                      │
│  模型加载 / 工作流执行│
│  图片生成 / 视频生成  │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│      本地模型库       │
│                      │
│  Checkpoint / LoRA   │
│  ControlNet / VAE    │
└──────────────────────┘
```

其中：

- 客户端不直接负责模型推理。
- Python 服务层负责管理任务和调用接口。
- ComfyUI 负责执行工作流。
- 模型库负责提供生成所需的模型文件。

这种方式可以将界面、业务逻辑和模型推理分开，后续更换客户端或调整工作流时也更方便。

## 五、ComfyUI 与 Ollama 如何配合？

如果已经了解 Ollama，也可以进一步将两者组合起来。

它们解决的是不同问题：

| 工具    | 主要能力                                     |
| ------- | -------------------------------------------- |
| Ollama  | 运行本地大语言模型，处理文本和部分多模态任务 |
| ComfyUI | 通过节点工作流执行图片、视频等生成任务       |
| Python  | 连接不同服务，组织业务流程                   |
| 客户端  | 提供用户操作界面                             |

例如，可以设计一个简单的 AI 图片助手：

1. 用户输入自然语言需求。
2. Ollama 根据需求整理提示词。
3. Python 获取提示词并选择对应的 ComfyUI 工作流。
4. ComfyUI 执行图片生成。
5. Python 获取生成结果。
6. 客户端展示图片。

示例：

```
用户：
生成一张日落时分的山水风景图

        │
        ▼

Ollama：
整理生成提示词

        │
        ▼

Python：
选择文生图工作流

        │
        ▼

ComfyUI：
执行图片生成

        │
        ▼

客户端：
展示最终图片
```

这只是一个简单的系统设计示例。

如果要进一步实现自动化，还可以让 Ollama 根据用户需求选择不同工作流，例如文生图、图片修复、背景替换或图片放大。

不过，模型选择、提示词生成和工作流执行最好保持相对独立，避免让大语言模型直接控制所有底层节点参数。

## 六、学习 ComfyUI 需要什么样的电脑？

ComfyUI 对硬件的要求与模型架构、分辨率、批量大小、视频帧数和量化方式密切相关。

下面是 NVIDIA 显卡显存的粗略参考：

|    显存     |                   适合的学习方向                   |
| :---------: | :------------------------------------------------: |
|     4GB     | 小型模型、低分辨率基础体验，部分工作流可能无法运行 |
|     6GB     |          部分 SD 1.5 工作流和轻量图片处理          |
|     8GB     |          基础文生图、图生图及部分轻量扩展          |
|    12GB     |             更多 SDXL 和图片处理工作流             |
|    16GB     |        较复杂的图像生成及部分轻量视频工作流        |
| 24GB 及以上 |         更适合高分辨率、较大模型和视频生成         |

以上只是经验参考，不是硬性门槛。

实际运行能力还受到以下因素影响：

- 模型是否支持量化。
- 是否使用低显存加载方式。
- 是否启用 CPU 卸载。
- 图片分辨率和批量大小。
- 是否同时加载多个模型。
- 自定义节点的资源需求。

如果电脑显存较小，建议先从 SD 1.5 等相对轻量的图片工作流开始，逐步学习模型管理、节点连接和 API 调用。

对于视频生成，不建议仅凭显存容量判断能否运行，最好先确认目标模型的官方硬件要求和 ComfyUI 工作流说明。

## 七、整理一份长期维护清单

学习结束后，可以建立一个长期维护清单。

### 7.1 模型管理

- 按模型类型整理目录。
- 记录模型名称、架构和来源。
- 检查模型文件是否完整。
- 删除不再使用的重复模型。
- 记录模型许可和使用限制。

### 7.2 工作流管理

- 保存常用文生图工作流。
- 保存图生图和局部重绘工作流。
- 保存图片修复和放大工作流。
- 保存视频生成工作流。
- 保存 API 格式工作流。
- 记录自定义节点及版本依赖。

### 7.3 环境管理

- 记录 ComfyUI 版本。
- 记录 Python 环境和依赖。
- 记录启动参数。
- 备份配置文件。
- 定期检查自定义节点兼容性。

### 7.4 项目管理

- 保留原始输入图片。
- 保存生成结果和参数。
- 记录任务执行状态。
- 对重要工作流进行版本管理。
- 定期测试备份是否能够恢复。

建议在每次升级 ComfyUI 或自定义节点之前，先备份当前环境和重要工作流。不要在正在使用的环境中盲目更新所有节点，否则可能导致原本正常的工作流无法运行。
