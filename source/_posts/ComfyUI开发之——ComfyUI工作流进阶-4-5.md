## 一、概述

```
前面我们已经学习了 ComfyUI 的基础节点、工作流导入、自定义节点安装和常见错误排查。

最初的文生图工作流通常比较简单：
 加载模型 → 提示词编码 → 采样 → 解码 → 保存图片


但在实际使用中，我们经常需要完成更复杂的任务：

- 同一张图片使用多个提示词生成不同效果。
- 同一模型尝试多种采样参数。
- 批量处理多张图片。
- 将一张图片同时进行放大、修复和风格转换。
- 将多个处理步骤组合成一个工作流。
- 减少重复节点和重复操作。

这些需求可以通过工作流分支、批量处理、参数复用和流程优化实现。
```

## 二、工作流分支概念

### 2.1、什么是工作流分支？

工作流分支，就是让一部分数据同时流向多个处理节点。

例如，加载一张图片后，希望分别进行：

- 普通图片缩放。
- AI 高清放大。
- 图片风格转换。

就可以将同一张图片连接到多个不同的处理分支。

```
                Load Image
                    │
          ┌─────────┼─────────┐
          │         │         │
          ▼         ▼         ▼
      Image Scale  AI放大   风格转换
          │         │         │
          ▼         ▼         ▼
       Save A    Save B    Save C
```

这三个分支可以分别完成不同的处理任务。

需要注意，分支只是共享输入数据，不代表所有节点都一定同时执行。ComfyUI 会根据最终输出节点及其依赖关系决定执行哪些节点。

### 2.2、如何搭建一个简单的分支工作流？

以图片处理为例。

#### 1. 加载原始图片

添加：

```
Load Image
```

选择一张本地图片。

这个节点输出 IMAGE 数据。

#### 2. 添加多个处理节点

例如：

- Image Scale：普通缩放。
- ImageUpscaleWithModel：AI 放大。
- Image Crop：图片裁剪。

将 Load Image 的 IMAGE 输出分别连接到各个节点。

#### 3. 分别保存结果

每个分支添加一个 Save Image 节点。

建议设置不同的文件名前缀：

```
branch/scale
branch/upscale
branch/crop
```

运行工作流后，可以分别查看三个分支的处理结果。

#### 4. 分支有什么优势？

分支可以让你：

- 对比不同处理方式。
- 使用同一张原图生成多种效果。
- 避免重复加载输入图片。
- 将多个任务整合到一个工作流。

特别适合图片修复、高清放大、风格对比和人物照片处理。

## 三 工作流分支相关操作

### 3.1、批量生成图片

ComfyUI 支持批量处理。

批量处理主要有两种常见方式：

1. 使用节点的 Batch Size。
2. 使用图片批次或循环类节点。

#### 1. 使用 Batch Size

在传统文生图工作流中，Empty Latent Image 通常包含：

```
width
height
batch_size
```

其中 Batch Size 表示一次创建多少张潜空间样本。

例如：

```
width = 512
height = 512
batch_size = 4
```

表示创建 4 个样本供后续采样。

不过需要注意：

- Batch Size 越大，显存需求通常越高。
- 每张图片可能对应不同随机结果。
- 批量生成不等于多次独立运行。
- 某些节点对批次数据的处理方式不同。

显存不足时，建议先从 Batch Size = 1 开始。

#### 2. 使用图片批次

如果要处理多张输入图片，可以使用支持批次输入的节点。

例如：

```
Load Image
    │
    ▼
图片批次处理
    │
    ▼
图片缩放
    │
    ▼
Save Image
```

部分工作流会使用专门的图片批次加载、合并或拆分节点。

这些节点通常来自 ComfyUI 自带功能或自定义节点包，具体名称和接口可能随版本变化。

#### 3. 批量处理与循环的区别

Batch Size、图片批次和循环并不是完全相同的概念。

| 方式           | 主要用途                   |
| -------------- | -------------------------- |
| Batch Size     | 一次生成多个样本           |
| 图片批次       | 将多张图片作为批次数据处理 |
| 循环节点       | 对输入数据重复执行某些操作 |
| Queue 多次运行 | 重复执行整个工作流         |

如果只是生成多张图片，Batch Size 或 Queue 通常就够了。

如果需要对大量不同图片执行相同处理，可能需要批次节点、循环节点或 Python 自动化。

### 3.2、使用 Queue 批量生成

ComfyUI 的 Queue 功能可以重复执行工作流。

例如，想生成多张不同 Seed 的图片，可以使用队列功能。

基本操作：

1. 设置好提示词和模型。
2. 设置 Seed 的变化方式。
3. 将工作流加入队列。
4. 根据需要调整队列数量。
5. 等待任务执行完成。

部分版本和工作流支持设置运行后自动变化 Seed。

需要注意，Queue 多次运行和 Batch Size 的区别：

- Queue：多次执行整个工作流。
- Batch Size：一次执行中处理多个样本。

如果显存有限，通常可以使用较小 Batch Size，通过 Queue 多次运行来生成图片。

### 3.3、参数复用：避免重复设置

参数复用是提高工作流效率的重要方式。

例如，工作流中有多个 KSampler，如果每个节点都单独设置 Seed、Steps、CFG，就容易出现参数不一致。

可以考虑以下方式。

#### 1. 使用 Primitive 节点

ComfyUI 中的 Primitive 类节点可以用于创建基础参数。

例如：

- 整数 INT。
- 浮点数 FLOAT。
- 字符串 STRING。
- 布尔值 BOOLEAN。

不同版本可能使用 Primitive、Primitive Node 或其他相关名称。

例如，使用一个 INT 参数控制多个节点中的相同设置：

```
           Primitive INT
                │
         ┌──────┴──────┐
         │             │
         ▼             ▼
      Node A        Node B
```

这样修改参数时，可以减少重复操作。

但需要注意，Primitive 能否连接到某个节点输入，取决于对应的数据类型和接口。

#### 2. 使用节点输入转换

有些参数可能不是直接的 INT 或 FLOAT。

例如：

- Seed
- Steps
- CFG
- 图片宽度
- 图片高度

可以根据节点实际输入类型选择对应参数节点。

如果连接失败，先检查数据类型是否一致。

#### 3. 使用自定义节点实现参数管理

部分自定义节点包提供：

- 参数集中管理。
- 多节点参数同步。
- 工作流配置预设。
- 参数面板。
- 节点组或便捷控制节点。

这些功能适合复杂工作流。

不过，安装第三方参数管理节点时，需要考虑节点依赖和兼容性。

初学阶段建议先熟悉原生节点，再逐步扩展。

### 3.4、节点组：让复杂工作流更整洁

当工作流越来越复杂时，画布可能会出现大量节点和连线。

例如：

```
模型加载
文本编码
ControlNet
IP-Adapter
采样
VAE解码
高清放大
保存图片
```

如果所有节点都直接铺在画布上，阅读和修改会越来越困难。

这时可以考虑使用节点组（Node Group）。

节点组的作用是将多个节点组织成一个逻辑模块。

例如：

```
┌─────────────────────┐
│     文本编码模块     │
│                     │
│ CLIP Text Encode    │
│ 正向提示词          │
│ 负向提示词          │
└─────────────────────┘
```

节点组可以帮助：

- 减少画布视觉复杂度。
- 将功能相近的节点放在一起。
- 提高工作流可读性。
- 方便分享和维护。

不同 ComfyUI 版本对节点组的功能和操作方式可能有所差异。

如果当前版本支持节点组，可以尝试将提示词编码、图片预处理或其他重复模块进行整理。

需要注意：节点组只是组织工作流的一种方式，不一定会自动减少显存占用或计算量。

### 3.5、工作流优化：减少重复计算

工作流优化不只是减少节点数量，更重要的是减少不必要的计算。

#### 1. 避免重复加载模型

模型加载通常比较耗时，也可能占用大量显存。

如果多个分支可以共享同一个模型加载节点，就尽量不要重复加载相同模型。

例如：

```
          Load Checkpoint
                 │
          ┌──────┴──────┐
          │             │
          ▼             ▼
       KSampler A    KSampler B
```

这样可以共享模型数据。

但如果不同分支使用不同模型，仍然需要分别加载。

#### 2. 复用中间处理结果

例如：

```
Load Image
    │
    ▼
图片预处理
    │
    ├──→ ControlNet
    │
    └──→ 图片合成
```

如果多个分支需要同一份预处理结果，可以尽量复用。

这样能够避免重复执行相同处理。

#### 3. 先低分辨率测试

复杂工作流可能包含：

- 图生图。
- ControlNet。
- IP-Adapter。
- 多次采样。
- 高清放大。
- 局部重绘。

如果直接使用高分辨率运行，容易浪费时间和显存。

建议：

1. 先用低分辨率测试流程。
2. 确认节点和参数正常。
3. 检查生成效果。
4. 最后再提高分辨率。

#### 4. 减少不必要的节点

有些工作流包含大量预览、重复缩放或多次图片转换节点。

如果某个节点没有实际用途，可以考虑删除。

但是，删除前必须确认它没有被其他节点依赖。

对于复杂工作流，建议先复制一份再修改。

## 四、实战：制作一个图片效果对比工作流

这次制作一个简单的图片处理对比工作流。

目标：同一张图片分别进行普通缩放和 AI 放大。

### 4.1. 添加节点

需要准备：

- Load Image
- Image Scale
- UpscaleModelLoader
- ImageUpscaleWithModel
- 两个 Save Image

AI 放大还需要下载对应的 Upscale Model。

### 4.2. 连接普通缩放分支

```
Load Image
    │
    ▼
Image Scale
    │
    ▼
Save Image
```

### 4.3. 连接 AI 放大分支

```
Load Image
    │
    ▼
ImageUpscaleWithModel
    │
    ▼
Save Image
```

同时将 UpscaleModelLoader 的模型输出连接到 ImageUpscaleWithModel。

### 4.4 设置不同文件名前缀

普通缩放：

```
compare/normal
```

AI 放大：

```
compare/ai_upscale
```

### 4.5. 运行并对比

运行工作流后，比较两张图片：

- 图片尺寸是否相同。
- 普通缩放是否出现模糊。
- AI 放大是否增加细节。
- AI 放大是否产生不真实纹理。

通过这次练习，可以理解分支、模型复用和图片处理流程。

## 五、常见问题

| 问题                    | 可能原因               | 解决方法                   |
| ----------------------- | ---------------------- | -------------------------- |
| 分支没有执行            | 没有连接到输出节点     | 检查最终输出依赖           |
| Batch Size 太大无法运行 | 显存不足               | 降低 Batch Size            |
| 批量图片没有全部处理    | 节点不支持当前批次输入 | 检查节点接口和批次处理能力 |
| Primitive 无法连接      | 数据类型不匹配         | 检查输入类型               |
| 工作流节点太多          | 缺少模块化整理         | 使用节点组或分区整理       |
| 生成速度慢              | 重复计算或模型加载     | 复用模型和中间结果         |
| 删除节点后工作流失败    | 删除了关键依赖         | 恢复节点并检查连线         |

## 六、总结

工作流进阶的核心，不是单纯增加节点，而是让生成流程更加灵活和高效。

本篇学习了：

- 工作流分支。
- Batch Size 和图片批次。
- Queue 多次运行。
- Primitive 参数复用。
- 节点组。
- 模型和中间结果复用。
- 减少重复计算。

当你能够使用这些方法时，就可以从简单的文生图工作流，逐步搭建复杂的图片处理流程。

建议在学习过程中，始终保留原始工作流副本，并逐步修改、测试和优化。
