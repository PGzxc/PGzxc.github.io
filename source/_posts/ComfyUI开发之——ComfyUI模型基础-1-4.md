## 一、前言

```
ComfyUI 模型基础：Checkpoint、VAE、CLIP、LoRA 概念与存放位置

第一次接触 ComfyUI 时，很多人会发现，下载模型并不像下载普通软件那么简单。
打开模型网站，可能会看到：Checkpoint、LoRA、VAE、CLIP、ControlNet、Upscale Model
这些文件有什么区别？是不是下载一个模型就能生成图片？不同模型之间能不能混用？

其实，这些模型承担着不同的任务。
有些负责生成图片，有些负责理解提示词，有些负责调整图片风格，
还有些负责控制人物姿势或提高图片清晰度。

本文就从最常见的几种模型开始，逐步理解它们的作用、关系和存放位置。
```

## 二、Checkpoint：图像生成的基础模型

### 2.1 Checkpoint 理解

```
Checkpoint 通常可以理解为图像生成的基础模型。
它包含模型训练得到的主要参数，能够根据提示词和其他条件生成图片。

例如，你输入： 
`一只橘猫坐在窗台上，阳光照射进房间，真实摄影风格。`

模型会根据提示词和生成过程，逐步得到一张符合描述的图片。
```

### 2.2 Checkpoint 有什么作用？

```
不同的 Checkpoint，生成效果可能存在很大差异。

例如：

- 有些模型擅长生成真实人物。
- 有些模型擅长动漫和插画。
- 有些模型擅长风景、建筑和产品图片。
- 有些模型更适合特定艺术风格。

因此，即使使用相同的提示词和生成参数，换一个 Checkpoint，也可能得到完全不同的结果。
```

### 2.3 Checkpoint 常见格式

1.常见的文件格式有：

|      格式      |                             说明                             |
| :------------: | :----------------------------------------------------------: |
| `.safetensors` | 常见的模型文件格式，设计上避免了传统 Pickle 序列化格式的一些安全风险 |
|    `.ckpt`     | 较早期常见的模型文件格式，可能使用 Pickle 序列化，加载不可信文件存在安全风险 |

2.说明：

```
如果下载模型，通常优先选择可信来源提供的 `.safetensors` 文件。

需要注意，文件后缀只代表文件格式，并不能判断模型属于 SD 1.5、SDXL 还是 FLUX，
也不能仅凭后缀判断模型是否兼容。
```

### 2.4 Checkpoint 存放位置

传统的完整 Checkpoint 模型通常放在：

```
ComfyUI/
└── models/
    └── checkpoints/
        ├── model_a.safetensors
        └── model_b.safetensors
```

放入后，可以在对应的模型加载节点中选择。

常见节点名称：

```
Load Checkpoint
```

### 2.5 一个 Checkpoint 是否包含所有内容？

```
传统 Stable Diffusion Checkpoint 通常可以同时包含：

- MODEL：负责图像生成的主要模型部分。
- CLIP：负责文本编码的部分。
- VAE：负责潜在图像与普通图像之间转换的部分。

例如，ComfyUI 中的 `Load Checkpoint` 节点通常可以输出 MODEL、CLIP 和 VAE 三种数据。

不过，并不是所有新模型都采用这种完整打包方式。
有些模型会将扩散模型、文本编码器和 VAE 分别提供，需要通过不同的加载节点组合使用。
这也是为什么下载模型时，必须查看模型页面和对应工作流的说明。
```

## 三、VAE：负责潜在图像与普通图片之间的转换

### 3.1 介绍

```
VAE 的英文全称是 Variational Autoencoder，中文通常称为变分自编码器。

对于刚接触 ComfyUI 的用户，可以先把它理解为：
 负责将模型内部使用的潜在图像数据转换成普通图片，以及在图像处理任务中完成反向编码。
```

### 3.2 为什么需要 VAE？

```
图像生成模型并不一定直接在普通 RGB 图片上完成全部计算。
以经典 Stable Diffusion 工作流为例，生成过程通常在 Latent（潜在空间）中进行。
当采样完成后，还需要通过 VAE 解码，才能得到可以正常查看和保存的图片。

可以简单理解为：

  潜在图像数据
      ↓
   VAE 解码
      ↓
   普通图片
   
如果没有正确使用 VAE，可能出现颜色异常、画面发灰、对比度不正常等问题。   
```

### 3.3 VAE 有什么作用？

```
VAE 主要涉及两个方向：
- VAE Encode：将普通图片编码为潜在图像数据。
- VAE Decode：将潜在图像数据解码为普通图片。

在文生图中，通常会使用 VAE Decode。
在图生图、局部重绘等场景中，可能需要先使用 VAE Encode。
```

### 3.4 VAE 存放位置

```
1.存放位置(独立 VAE 模型通常放在)：
ComfyUI/
└── models/
    └── vae/
        ├── vae_a.safetensors
        └── vae_b.safetensors
                
2.常见节点：
- `Load VAE`
- `VAE Encode`
- `VAE Decode`


如果 Checkpoint 已经包含适配的 VAE，通常可以直接使用加载 Checkpoint 节点输出的 VAE，不需要另外下载。
如果工作流要求使用独立 VAE，则需要单独加载，并按照工作流要求连接。  

注意：VAE 也有模型兼容性要求，不能认为任何 VAE 都可以搭配任何 Checkpoint 使用。
```

## 四、CLIP：负责理解提示词

### 4.1 介绍

```
1.说明：
CLIP 是一种图像与文本相关的编码模型。
在经典 Stable Diffusion 文生图工作流中，它负责将输入的文字提示词转换成模型能够使用的条件信息。

2.例如：
输入提示词：
一只橘猫坐在窗台上，阳光照射进房间
          ↓
       CLIP 编码
          ↓
    文本条件信息
          ↓
      参与图片生成
      
      
可以把 CLIP 理解为模型与文字之间的桥梁。      
```

### 4.2 CLIP 有什么作用？

```
当你输入：
 a cat sitting on the sofa

CLIP 会对文本进行编码，生成相应的条件信息。
随后，图像生成模型会结合这些条件，逐步生成符合描述的图片。
如果没有正确的文本编码器，模型可能无法按照预期理解提示词。
```

### 4.3 CLIP 存放位置

```
1.根据模型架构和加载方式，CLIP 或相关文本编码器通常放在：
ComfyUI/
└── models/
    ├── clip/
    └── text_encoders/
    
    
2.常见节点包括：

- `Load CLIP`
- `CLIP Text Encode (Prompt)`
- `DualCLIPLoader`

具体使用哪个目录、哪个节点，要看模型和工作流要求。    
```

### 4.4 为什么有些模型需要单独下载 CLIP？

```
因为不同模型使用的文本编码器并不完全相同。

传统的Stable Diffusion Checkpoint可能已经包含文本编码器，而一些新架构会将文本编码器独立提供。

例如，部分 FLUX 工作流需要额外准备文本编码器，不能只下载一个扩散模型就直接运行。
因此，下载模型时要特别留意是否还需要配套的文本编码器。
```

## 五、LoRA：在基础模型上增加特定效果

### 5.1 介绍

```
LoRA 的英文全称是 Low-Rank Adaptation，中文通常称为低秩适配。

如果说 Checkpoint 是基础模型，
那么 LoRA 就可以理解为在基础模型上增加某种特定风格、人物特征或概念能力的轻量化模型文件。
```

### 5.2 LoRA 有什么作用？

```
假设你使用一个基础模型，能够生成普通的真实人物图片。

但你希望图片具有特定效果，例如：

- 水墨画风格。
- 日系动漫风格。
- 特定人物形象。
- 特定服装或发型。
- 特定光影和摄影效果。

这时可以尝试使用相应的 LoRA。

它不需要像完整 Checkpoint 一样重新提供全部基础模型参数，而是通过额外参数对基础模型进行调整。
```

### 5.3 LoRA 和 Checkpoint 有什么区别？

| 对比             | Checkpoint                 | LoRA                       |
| ---------------- | -------------------------- | -------------------------- |
| 主要作用         | 提供基础生成能力           | 调整或增加特定效果         |
| 文件体积         | 通常较大                   | 通常较小                   |
| 是否依赖基础模型 | 本身作为基础模型使用       | 通常需要匹配的基础模型     |
| 使用方式         | 加载基础模型               | 加载后应用到模型           |
| 适用场景         | 决定整体生成能力和风格基础 | 增加人物、风格、服装等特征 |

例如：

```
你可以使用一个写实风格 Checkpoint，再叠加一个适配它的服装 LoRA，让生成图片具有特定服装效果。
```

### 5.4 LoRA 存放位置

```
1.位置：通常放在：
ComfyUI/
└── models/
    └── loras/
        ├── style_a.safetensors
        └── character_b.safetensors
        
2.2 常见节点：
Load LoRA

这个节点通常有两个重要参数：

- `strength_model`：LoRA 对生成模型的影响强度。
- `strength_clip`：LoRA 对文本编码器的影响强度。
```

日常使用时，通常从 0.5～1.0 左右开始尝试，再根据模型说明和实际效果调整。

例如：

|   权重   |      可能产生的效果      |
| :------: | :----------------------: |
|    0     |  不应用 LoRA 的调整效果  |
|   0.5    |        较弱的影响        |
|   0.8    |       较明显的影响       |
|   1.0    |      按默认强度应用      |
| 大于 1.0 | 更强的影响，但不一定更好 |

这些数值只是调试起点，不是固定标准。不同 LoRA 的训练方式和推荐权重可能不同。

### 5.5 LoRA 是否可以随意混用？

```
不可以。
LoRA 通常需要匹配相应的基础模型架构。

例如：
- SD 1.5 LoRA 通常用于 SD 1.5 系列模型。
- SDXL LoRA 通常用于 SDXL 系列模型。
- FLUX LoRA 通常用于对应的 FLUX 架构。

即使文件格式都是 `.safetensors`，也不代表它们可以相互使用。
下载 LoRA 时，应查看模型页面中的基础模型、触发词和推荐权重。
```

## 六、其他常见模型：ControlNet、CLIP Vision 和放大模型

除了前面介绍的四种模型，ComfyUI 还有一些常用的辅助模型。

### 6.1 ControlNet：控制图片结构

```
ControlNet 主要用于根据额外的结构信息控制生成结果。

例如：

- 使用人体姿势图控制人物动作。
- 使用边缘图控制物体轮廓。
- 使用深度图辅助控制空间结构。

它可以帮助模型更好地按照参考结构生成图片。

常见存放位置：ComfyUI/models/controlnet/
```

### 6.2 CLIP Vision：理解参考图片

```
CLIP Vision 与文本编码使用的 CLIP 相关，但它主要处理图像信息。

在某些参考图工作流中，可以通过它提取图片特征，再配合其他节点或模型使用。

例如，部分 IP-Adapter 工作流会使用 CLIP Vision。

常见存放位置：ComfyUI/models/clip_vision/

注意：CLIP Vision 不等于普通的文本编码器 CLIP，两者用途不同。
```

### 6.3 Upscale Model：图片放大模型

```
Upscale Model 用于提高图片分辨率或增强细节。

例如，生成一张 512×512 的图片后，可以使用放大模型处理成更高分辨率的图片。

常见存放位置：ComfyUI/models/upscale_models/

常见用途包括：

- 图片放大。
- 细节增强。
- 老照片清晰度改善。

不同放大模型的效果和适用场景不同，后续会专门介绍高清放大工作流。
```

## 七、这些模型之间是什么关系？

前面介绍了多种模型，如果只记住每个模型的定义，实际搭建工作流时仍然容易混淆。

下面通过一个经典的 Stable Diffusion 文生图流程，理解它们之间的关系。

### 7.1 经典文生图流程

```
           Checkpoint
               │
        ┌──────┼──────┐
        │      │      │
      MODEL   CLIP   VAE
        │      │      │
        │   输入提示词  │
        │      │      │
        │   文本编码   │
        │      │      │
        └──→ 采样生成  │
                │     │
             Latent   │
                │     │
                └→ VAE解码
                      │
                   保存图片
```

这是传统完整 Checkpoint 工作流的简化示意。

如果使用 LoRA，可以将它加入基础模型和文本编码器的处理链路中。

如果使用 ControlNet，则可以增加额外的图像条件，对生成过程进行控制。

如果使用独立 VAE 或独立文本编码器，则需要根据模型架构使用相应的加载节点。

### 7.2 模型之间的关系总结

|     模型      |          主要职责          |     常见应用     |
| :-----------: | :------------------------: | :--------------: |
|  Checkpoint   |      提供基础生成能力      |  文生图、图生图  |
|      VAE      | 潜在图像与普通图像之间转换 |    编码、解码    |
|     CLIP      |    将文字转换为条件信息    |    提示词编码    |
|     LoRA      |   调整基础模型的特定效果   | 风格、人物、服装 |
|  ControlNet   |      提供结构控制条件      | 姿势、边缘、深度 |
|  CLIP Vision  |      提取参考图片特征      |    参考图生成    |
| Upscale Model |     图片放大和细节增强     |     高清处理     |

需要注意，这张表主要用于理解各类模型的用途，并不代表所有模型都必须同时使用。

## 八、不同模型架构有什么区别？

前面主要以经典 Stable Diffusion 工作流为例，但 ComfyUI 并不只支持 Stable Diffusion。

目前常见的图像生成模型包括 SD 1.5、SDXL、FLUX 和 Qwen Image 等。

它们在模型结构、文本编码方式、模型文件组织和硬件要求方面都有区别。

| 模型体系   | 特点                                                     | 使用时需要注意                 |
| ---------- | -------------------------------------------------------- | ------------------------------ |
| SD 1.5     | 生态成熟，资源丰富                                       | 适合入门，模型和 LoRA 选择较多 |
| SDXL       | 相比 SD 1.5，模型结构和生成能力有所升级                  | 通常需要更多显存和配套资源     |
| FLUX       | 新一代图像生成模型体系，支持相应的高质量生成与编辑工作流 | 注意文本编码器、VAE 和显存要求 |
| Qwen Image | 支持图像生成及相关图像编辑能力                           | 按对应模型版本和工作流准备文件 |

这里需要特别注意：

```
不同模型体系之间，不能简单地混用 Checkpoint、LoRA、VAE 和文本编码器。

例如，SD 1.5 的 LoRA 不能直接拿来当作 SDXL 的 LoRA 使用。FLUX 和 Qwen Image 也有各自的模型结构和加载方式。

所以，下载模型时不能只看图片效果，还要看它适用于哪一种基础模型。
```

```
可以搜索：

```

```
Civitai 是一个常见的 AI 图像模型分享社区。
```

```
一些模型会在官方 GitHub 或其他项目页面发布。

```

### 9.4 下载模型时需要注意什么？

```
下载之前，建议检查：

1. 模型属于哪种架构。
2. 文件是什么类型。
3. 是否需要配套的 VAE、CLIP 或其他文件。
4. 推荐使用什么节点和工作流。
5. 模型需要多少显存和磁盘空间。
6. 模型许可是否允许个人使用或商业使用。

模型文件通常比较大，建议优先下载当前学习任务需要的模型，不要一次性下载大量文件。
```

## 十、动手练习：认识模型目录

现在可以打开自己的 ComfyUI 安装目录，完成几个简单操作。

1. 找到 `models` 目录。
2. 查看 `checkpoints`、`loras`、`vae` 等子目录。
3. 如果已经下载了模型，检查文件是否放在对应位置。
4. 打开 ComfyUI，找到模型加载相关节点。
5. 查看节点中的模型下拉列表，确认模型是否被识别。
6. 如果刚刚复制了模型文件，可以按当前版本支持的方式刷新模型列表；必要时重启 ComfyUI。

如果还没有下载模型，也不用着急。下一篇会正式搭建第一个文生图工作流，到时候再根据实际需要准备对应模型。

## 十一、总结

这一篇介绍了 ComfyUI 中常见的模型类型。

初学阶段，建议先记住以下几个概念：

- **Checkpoint：** 基础生成模型，决定整体生成能力。
- **VAE：** 负责潜在图像与普通图片之间的转换。
- **CLIP：** 负责将文本提示词转换为条件信息。
- **LoRA：** 在基础模型上增加或调整特定效果。
- **ControlNet：** 根据姿势、边缘、深度等信息控制生成结构。
- **CLIP Vision：** 处理参考图片特征。
- **Upscale Model：** 用于图片放大和细节增强。

还要记住，模型文件的后缀相同，不代表模型类型相同；模型能够被 ComfyUI 识别，也不代表它一定能与当前工作流兼容。

先理解模型的作用，再学习如何组合它们，后续搭建工作流就会容易很多。
