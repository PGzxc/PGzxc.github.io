## 一、前言

```
刚安装 ComfyUI 时，很多新手会遇到几个问题：

- ComfyUI 应该从哪里下载？有哪几种安装方式？
- 软件启动后，为什么找不到模型？
- `models`、`checkpoints`、`loras` 等目录分别有什么作用？
- 如何修改启动参数？
- 能否把模型放在其他磁盘，或者与 Stable Diffusion WebUI 共用模型？

这些问题看起来比较零散，但都与 ComfyUI 的安装方式、目录结构和配置有关。

本文以 Windows 本地环境为主，介绍常见的安装方式、主要目录、模型存放位置和基础配置。
Linux、macOS 用户也可以参考其中的目录与配置思路，但具体操作可能有所不同。
```

## 二、ComfyUI 有哪些安装方式？

ComfyUI 常见的使用方式主要有三种：桌面版、Windows 便携版和手动安装版。

### 2.1 桌面版：适合新手

```
桌面版提供相对完整的安装和管理体验，可以像普通软件一样安装和启动，并帮助配置运行环境。

优点：
- 安装过程相对简单。
- 不需要自己从头配置 Python 环境。
- 适合刚接触 ComfyUI 的用户。

如果你主要目的是学习节点、搭建工作流和生成图片，建议优先考虑桌面版。

官方下载：ComfyUI 下载页面：https://www.comfy.org/download
```

### 2.2 Windows 便携版：适合希望直接管理文件的用户

```
便携版通常将 ComfyUI 程序和独立的 Python 运行环境放在同一个目录中，解压后即可通过启动脚本运行。

常见目录结构如下：
ComfyUI_windows_portable/
├── ComfyUI/
│   ├── models/
│   ├── custom_nodes/
│   ├── input/
│   ├── output/
│   └── user/
├── python_embeded/
├── update/
├── run_nvidia_gpu.bat
└── run_cpu.bat


实际目录可能因版本和安装包不同而有所变化。

便携版的优点是目录清晰，方便备份、迁移和手动管理模型。
缺点是部分配置、更新和扩展节点的维护工作需要自己处理。

官方项目：ComfyUI GitHub:https://github.com/Comfy-Org/ComfyUI
```

### 2.3 手动安装版：适合开发者和进阶用户

```
手动安装通常需要自行准备 Python、Git 以及与硬件匹配的 PyTorch 等依赖，
再下载 ComfyUI 项目并安装运行环境。

这种方式的优点是配置自由，适合调试环境、研究依赖和开发扩展节点。

但对于初学者，如果 Python 版本、PyTorch、显卡驱动或其他依赖不匹配，可能会遇到安装失败的问题。

因此，除非你有明确的开发需求，否则没有必要一开始就选择手动安装。
```

### 2.4 应该选择哪一种？

| 安装方式   | 适合人群               | 主要特点                 |
| ---------- | ---------------------- | ------------------------ |
| 桌面版     | 初学者                 | 安装和管理较方便         |
| 便携版     | 喜欢自己管理目录的用户 | 文件集中，迁移方便       |
| 手动安装版 | 开发者、进阶用户       | 配置自由，但需要维护依赖 |

建议：

```
先选定一种安装方式，再按照对应版本的官方文档操作。
不要把桌面版、便携版和手动安装版的目录、启动脚本或配置文件混在一起使用。
```

## 三、ComfyUI 的目录结构详解

安装完成后，先不要急着下载大量模型。建议先认识几个最常用的目录。

下面以常见的 ComfyUI 主目录为例：

```
ComfyUI/
├── models/
│   ├── checkpoints/
│   ├── loras/
│   ├── vae/
│   ├── controlnet/
│   ├── clip/
│   ├── diffusion_models/
│   ├── text_encoders/
│   └── upscale_models/
├── custom_nodes/
├── input/
├── output/
├── temp/
├── user/
├── main.py
└── extra_model_paths.yaml.example
```

不同版本、安装方式和模型架构可能会出现其他目录。上面列出的是常见目录，并不是所有安装都必须具备完全相同的结构。

### 3.1 `models`：模型存放目录

这是最重要的目录之一。

ComfyUI 需要根据模型类型加载相应的文件。为了方便管理，通常会将不同类型的模型放入不同子目录。

| 目录               | 主要用途                 |
| ------------------ | ------------------------ |
| `checkpoints`      | 存放传统的完整检查点模型 |
| `loras`            | 存放 LoRA 模型           |
| `vae`              | 存放独立的 VAE 模型      |
| `controlnet`       | 存放 ControlNet 模型     |
| `clip`             | 存放部分 CLIP 相关模型   |
| `diffusion_models` | 存放部分独立的扩散模型   |
| `text_encoders`    | 存放文本编码器           |
| `upscale_models`   | 存放图片放大模型         |

说明：

```
这些目录的作用不是简单地按文件后缀分类，而是按照模型在工作流中的用途分类。

例如，`.safetensors` 是一种常见的模型文件格式，但文件后缀相同，并不代表它们可以互相替代。
模型放在哪个目录，要以模型说明和对应工作流的要求为准。
```

### 3.2 `custom_nodes`：自定义节点目录

```
ComfyUI 自带常用节点，但一些工作流需要额外的自定义节点才能运行。

例如，某些节点用于：

- 图片处理与批量操作。
- 特定模型的加载与推理。
- 视频生成。
- 外部服务或 API 集成。

这些扩展通常放在 `custom_nodes` 目录下。

需要注意，自定义节点可能还依赖额外的 Python 包、模型文件或特定版本的 ComfyUI。把节点文件复制进去，不一定就意味着它能够正常运行。

建议初学阶段先使用官方基础节点。等到导入的工作流明确提示缺少某个节点时，再安装对应扩展。
```

### 3.3 `input`：输入图片目录

```
某些工作流需要读取本地图片，例如图生图、局部重绘和照片修复。

这类图片通常可以放在 `input` 目录中，再通过相应的加载图片节点选择。

具体支持哪些文件格式，取决于使用的节点及其实现。
```

### 3.4 `output`：生成结果目录

```
ComfyUI 生成并保存的图片，通常会放在 `output` 目录中。

完成图片生成后，可以在这个目录中查看结果。

如果你经常生成大量图片，建议定期整理输出文件，避免结果文件越来越多，占用大量磁盘空间。
```

### 3.5 `temp`：临时文件目录

```
部分处理过程会产生临时文件，通常放在 `temp` 目录中。

它不是用来长期保存最终作品的目录。
如果磁盘空间紧张，可以在确认没有任务正在运行后，再根据需要清理临时文件。
```

### 3.6 `user`：用户数据目录

```
部分版本会使用 `user` 目录保存用户相关数据，例如界面设置、工作流管理数据等。

具体内容会随版本和功能发生变化，因此不建议在不了解用途的情况下直接删除整个目录。
```

### 3.7 `main.py`：程序入口

```
对于便携版以外的一些安装方式，`main.py` 是常见的程序启动入口。

例如，在已经配置好 Python 和依赖的环境中，可以通过命令启动：

​```
python main.py
​```

但如果你使用的是桌面版或便携版，通常应该优先使用对应的应用程序或启动脚本，不要直接套用这条命令。
```

## 四、模型应该放在哪里？

### 4.1 放在哪里

```
这是 ComfyUI 初学阶段最常见的问题之一。

假设你下载了一个 Stable Diffusion 检查点模型，文件名是：example_model.safetensors

如果模型说明明确指出它是传统的 Checkpoint 模型，
通常可以放在：ComfyUI/models/checkpoints/example_model.safetensors

如果下载的是 LoRA 模型，常见位置则是：ComfyUI/models/loras/

但如果你下载的是 FLUX 或其他新架构模型，就不能只凭文件名或后缀，判断应该放在哪里。部分工作流需要独立的扩散模型、文本编码器、VAE 等多个文件。

因此，下载模型时应重点确认三个信息：
1. 模型属于哪一种架构和类型。
2. 模型需要哪些配套文件。
3. 对应工作流要求使用哪些节点和目录。
```

### 为什么模型已经放进去了，ComfyUI 还是找不到？

```
通常可以从以下几个方向排查：

- 文件放错了目录。
- 模型类型与当前节点不匹配。
- 文件没有完整下载。
- 模型目录被修改过，但配置没有同步更新。
- ComfyUI 尚未重新扫描模型，或者需要重启。
- 当前工作流使用的是另一种模型加载方式。

排查时，先核对模型说明和工作流要求，不要一遇到问题就重复下载同一个文件。
```

## 五、能否把模型放在其他磁盘？

### 5.1 可以

```
例如，你的系统盘空间有限，
但 D 盘有较大的空闲空间，就可以把模型集中放在 D 盘，而不必全部存放在 ComfyUI 的默认目录中。

这样做还有一个好处：如果同时使用多个 AI 绘图工具，可以减少同一模型的重复存储。

ComfyUI 支持通过 `extra_model_paths.yaml` 等配置方式添加额外的模型搜索路径。
不同安装版本的配置文件位置和格式可能有所区别。
```

### 1. 先准备模型目录

例如，在 D 盘建立统一的模型目录：

```
D:/AI/models/
├── checkpoints/
├── loras/
├── vae/
├── controlnet/
└── upscale_models/
```

然后将对应类型的模型放入相应子目录。

### 2. 找到配置示例文件

对于常见的便携版和手动安装版，可以在 ComfyUI 主目录中查找：

```
extra_model_paths.yaml.example
```

通常可以复制这个文件，并将副本命名为：

```
extra_model_paths.yaml
```

然后按照文件中的示例修改配置。

注意：桌面版的配置位置可能不同，应使用该版本文档中指定的配置文件，不要直接将便携版的配置文件覆盖到桌面版配置目录中。

### 3. 配置额外路径

下面是一个简化示例。假设模型存放在 `D:/AI/models/`：

```
my_models:
  base_path: "D:/AI/models/"
  checkpoints: checkpoints/
  loras: loras/
  vae: vae/
  controlnet: controlnet/
  upscale_models: upscale_models/
```

这里的 `my_models` 是自定义配置名称，可以自行修改。

`base_path` 指定模型目录的基础路径，后面的各项指定对应类型的子目录。

实际配置时，建议参考你当前版本附带的示例文件，并保留已有配置。不同版本可能支持不同的目录项，不能直接认为上面的示例覆盖所有模型类型。

修改完成后，保存配置并重启 ComfyUI，再检查相应模型是否能够被识别。

官方参考：[ComfyUI 模型路径配置说明](https://github.com/Comfy-Org/ComfyUI/blob/master/extra_model_paths.yaml.example)

## 六、ComfyUI 启动参数怎么设置？

启动参数用于调整 ComfyUI 的运行方式，例如修改端口、允许局域网访问，或者指定某些运行选项。

对于初学者，先认识几个常用参数即可，不需要一开始就修改所有设置。

### 1. 常见启动参数

| 参数                    | 作用                                   |
| ----------------------- | -------------------------------------- |
| `--port 8188`           | 指定 Web 服务端口                      |
| `--listen 0.0.0.0`      | 监听所有 IPv4 网络接口，便于局域网访问 |
| `--cpu`                 | 使用 CPU 运行，通常速度较慢            |
| `--lowvram`             | 在支持的运行模式下尝试降低显存占用     |
| `--disable-auto-launch` | 不自动打开浏览器                       |

这些参数的实际效果与当前版本、硬件和运行环境有关。尤其是显存相关选项，不要认为开启 `--lowvram` 就一定能够运行任何大型模型。

### 2. 如何修改启动参数？

如果使用便携版，通常可以检查对应的 `.bat` 启动脚本。

例如，原来的启动命令可能包含：

```
.\python_embeded\python.exe -s ComfyUI\main.py --windows-standalone-build
```

如果希望指定端口，可以在原有参数后面追加：

```
--port 8189
```

修改前建议备份原始脚本。不同版本的脚本内容可能不同，应以你实际安装的文件为准。

如果使用桌面版，应优先通过应用提供的设置项配置，不要假设它与便携版使用相同的启动脚本。

### 3. 如何访问 ComfyUI？

```
ComfyUI 默认端口通常是 `8188`。

在本机成功启动后，可以在浏览器中打开：http://127.0.0.1:8188
如果你修改了端口，例如设置为 `8189`，则应访问：http://127.0.0.1:8189

如果页面打不开，先检查命令行窗口是否显示启动成功，以及实际端口是否与浏览器地址一致。
```

### 4. 如何从手机或其他电脑访问？

```
如果你想让同一局域网内的手机、平板或另一台电脑访问 ComfyUI，
可以在确认网络环境可信的前提下，配置监听地址，例如：--listen 0.0.0.0

然后使用运行 ComfyUI 的电脑在局域网中的 IP 地址访问，例如：http://192.168.1.100:8188

其中的 IP 只是示例，应替换为你电脑的实际局域网 IP。

此外，还需要检查 Windows 防火墙和网络设置是否允许连接。

安全提醒：
不要为了方便，直接把未做安全防护的 ComfyUI 服务暴露到公网。
局域网访问与公网访问是两回事。
如果确实需要远程访问，应先设计好身份验证、网络隔离和访问控制。

官方参数参考：ComfyUI 启动参数文档 
```

## 七、安装完成后，先检查哪些设置？

第一次启动成功后，不需要立刻修改所有配置。建议先完成下面的基础检查。

### 1. 确认程序能够正常启动

```
检查终端窗口是否报错，浏览器是否能打开 ComfyUI 页面。
如果程序无法启动，先查看终端中的错误信息，不要只根据浏览器页面判断原因。
```

### 2. 确认模型能够被识别

```
如果已经下载了适配当前工作流的模型，检查它是否出现在对应的模型选择节点中。
如果没有出现，优先检查模型目录、配置路径以及模型类型。
```

### 3. 确认输入和输出目录

```
了解图片从哪里读取、生成结果保存在哪里。
建议将输入图片、模型和输出结果分开管理，便于后续整理和备份。
```

### 4. 暂时不要安装大量自定义节点

```
自定义节点能够扩展功能，但也可能带来依赖冲突、版本不兼容等问题。
刚入门时，先使用基础节点跑通一个简单工作流，再根据实际需要安装扩展，会更容易排查问题。
```

## 八、常见问题排查

### 8.1 常见问题

| 问题                   | 优先检查                                           |
| ---------------------- | -------------------------------------------------- |
| 双击启动脚本后立即退出 | 查看终端报错、Python 或 PyTorch 依赖、显卡驱动     |
| 浏览器无法打开页面     | 检查程序是否启动成功、端口是否正确                 |
| 模型列表中找不到文件   | 检查目录、模型类型和额外路径配置                   |
| 导入工作流提示缺少模型 | 按工作流说明补齐模型及其配套文件                   |
| 导入工作流提示缺少节点 | 确认缺失节点的名称、来源及兼容版本                 |
| 生成时提示显存不足     | 尝试降低分辨率、使用更轻量的模型或简化工作流       |
| 修改配置后没有变化     | 确认改的是当前安装版本使用的配置文件，并按要求重启 |

### 8.2 如何排查

```
遇到问题时，建议按照“确认安装版本 → 查看错误日志 → 核对模型和节点 → 检查配置”的顺序排查。
这样通常比反复重装更有效。
```

## 九、总结

这一篇主要介绍了 ComfyUI 的安装方式、目录结构、模型管理和基础启动配置。

记住几个关键目录即可：

```
- `models`：存放各类模型。
- `custom_nodes`：存放自定义节点。
- `input`：存放或读取输入图片。
- `output`：保存生成结果。
- `temp`：存放临时文件。
- `user`：存放部分用户数据。
- `main.py`：常见的程序启动入口。
```

注意事项：

```
如果模型较多，可以将模型放到其他磁盘，并通过额外模型路径配置让 ComfyUI 识别。

对于新手，现阶段最重要的不是记住所有参数，而是确认程序能够正常启动、理解模型存放位置，并知道出现问题时应该从哪里排查。
```
